# Quick Task 260511-l0p: PR #34 CI E2E failure recovery

## Goal

2026-05-11 PR #34 CI run `25651130883`의 `E2E tests (Toss Payments)` 실패를 앱 동작 기준으로 복구한다. `booking-floor-selection`은 한국 공연 시간이 항상 KST `19:00`으로 보여야 하고, `i18n-smoke`는 booking-disabled 상태에서 `/booking/:id`가 지연 없이 locale별 disabled copy를 노출해야 한다.

## Findings

- `apps/web/components/booking/showtime-chips.tsx`와 `apps/web/components/booking/booking-page.tsx`는 `new Date(...).toLocaleTimeString('ko-KR')` / `toLocaleDateString('ko-KR')`를 runner local timezone 기준으로 사용한다. `2026-07-18T19:00:00.000+09:00`가 UTC runner에서는 `10:00`으로 렌더링되어 `booking-floor-selection.spec.ts`가 `19:00` 버튼을 찾지 못한다.
- `apps/web/components/booking/booking-page.tsx`는 `performanceLoading` skeleton을 `bookingDisabledReason`보다 먼저 반환한다. 그래서 runtime flag가 `bookingEnabled=false`여도 performance detail query가 느리거나 일시적으로 비면 `예매는 5월말 오픈 예정입니다` guard가 5초 안에 보장되지 않는다.
- `apps/web/playwright.config.ts`는 web server만 띄우고 API는 별도 기동해야 한다. API 없이 돌린 local Playwright는 CI 회귀와 무관한 `ECONNREFUSED ::1:8080`를 만든다. 재현/검증은 `.github/workflows/ci.yml`의 topology를 그대로 따라야 한다.

## Plan

- `availableDates`, `filteredShowtimes`, desktop summary, `ShowtimeChips`가 같은 formatter를 쓰도록 맞춘다. 한쪽만 KST로 고치고 다른 쪽은 local timezone을 남겨두는 식의 partial fix는 금지한다.
- E2E spec의 기대값 `2026년 7월 18일 토요일` / `19:00`는 유지한다. 테스트를 local timezone에 맞춰 느슨하게 바꾸지 않는다.

**Done when**

### Task 2: booking-disabled guard를 performance loading보다 먼저 노출하고 locale copy 회귀를 테스트로 고정한다

**Files**
- Modify: `apps/web/components/booking/booking-page.tsx`
- Modify: `apps/web/hooks/__tests__/booking-disabled-runtime.test.tsx`

**Action**
- runtime flags가 resolve된 뒤 `bookingEnabled=false`이면 performance detail fetch 완료를 기다리지 말고 disabled guard를 먼저 렌더링한다.
- booking-disabled 상태에서는 queue gate와 seat-map 계산보다 "예매 불가" 사실을 우선 surface한다. performance title이 아직 없으면 skeleton이나 fallback label을 허용하되, disabled copy 자체는 즉시 보이게 한다.
- `apps/web/app/booking/[performanceId]/page.tsx`의 queue/runtime-flag contract는 유지하되, runtime flag resolution 판정은 reactive hook state로 읽는다. `queryClient.getQueryState()` snapshot은 disabled UI를 계속 queue loading 뒤에 둘 수 있어 제거한다.
- `booking-disabled-runtime.test.tsx`에 "performance detail is loading or missing even though booking is disabled" 케이스를 추가해서, 다섯 locale 중 최소 `ko`와 `en` copy가 loading state보다 먼저 노출되는지 검증한다.
- i18n smoke를 맞추기 위해 copy literal을 바꾸지 않는다. 현재 `예매는 5월말 오픈 예정입니다` / `Ticket booking opens in late May` contract를 유지한 채 노출 타이밍만 고친다.

**Done when**
- `/booking/:id`는 booking-disabled 상태에서 performance query 속도와 무관하게 disabled copy를 먼저 보여준다.
- locale-specific disabled copy contract가 unit test로 고정된다.
