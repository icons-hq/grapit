# Quick Task 260507-ji6: Language switch does not update UI copy

## Root Cause

The desktop locale switcher uses `router.push()` to move from `/` to `/en`.
Because this app uses flat App Router routes plus a proxy rewrite for locale
prefixes, the browser URL and `usePathname()` update, but the root
`NextIntlClientProvider` in `app/layout.tsx` stays mounted with the previous
`ko` locale during client-side navigation. The switcher label is derived from
the pathname, so it shows English, while UI copy derived from `useLocale()`
continues to render Korean.

Directly loading `/en` works, which confirms messages and API locale handling
are not the primary failure.

## Plan

1. Update `LocaleSwitcher` so explicit language changes perform a document
   navigation to the localized path after persisting the preference. This
   forces a fresh request through the proxy and remounts the locale provider
   with the target locale.
2. Localize currently hardcoded visible genre/navigation labels in the public
   shell surfaces so that after the provider is correct, the desktop GNB,
   genre grid, mobile menu, and mobile tab bar do not keep Korean static copy.
3. Add focused regression coverage for locale switch navigation and visible
   genre/tab copy, then run targeted tests and browser-check the desktop
   switcher flow.

## Verification

- `pnpm --filter @grabit/web test -- app/__tests__/home-i18n.test.tsx components/layout/__tests__/gnb-locale.test.tsx`
- Browser desktop flow: `/` -> language menu -> `English` -> URL `/en` and visible English home/nav copy.
