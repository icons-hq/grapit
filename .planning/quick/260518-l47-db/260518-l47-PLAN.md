<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member browser -> user API | Authenticated member sends destructive account lifecycle request. |
| admin browser -> admin API | Privileged admin sends soft withdrawal or hard-delete request for another user. |
| API -> database | Account lifecycle writes, audit writes, token revocation, and physical delete cross into persistent storage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-260518-L47-01 | S | `/users/me/withdrawal` | mitigate | Require authenticated `CurrentUser`; do not accept user id from body for self withdrawal. |
| T-260518-L47-02 | T | Admin lifecycle endpoints | mitigate | Guard with `RolesGuard`, `AdminCapabilitiesGuard`, and `security.manage`; validate body with zod. |
| T-260518-L47-03 | R | Withdrawal and hard-delete actions | mitigate | Require `reason` and `confirmed: true`; write masked audit rows with actor, resource id, request id, IP, and user-agent. |
| T-260518-L47-04 | I | Audit snapshots and UI errors | mitigate | Use `AdminAuditService` masking and return blocker categories/counts rather than raw related records. |
| T-260518-L47-05 | D | Accidental active-ticket account withdrawal | mitigate | Block self/admin withdrawal while active `PENDING_PAYMENT` or future `CONFIRMED` reservations exist. |
| T-260518-L47-06 | E | Admin self-lockout or last-admin deletion | mitigate | Reuse last security-manage admin checks and reject actor self hard-delete. |
</threat_model>
