# Quick Task 260507-ok2: Investigate and fix prod CD migration failure via CLI

## Goal

`CI`는 통과하지만 `Deploy`가 production migration 단계에서 실패하는 원인을 CLI 로그로 고정하고, 배포 경로만 좁게 패치한 뒤 로컬에서 재현 기반 검증까지 끝낸다.

## Findings locked before execution

- 실패 run은 `Deploy` run `25484595049`이며, `deploy-api`의 `Run migrations` 단계에서 중단됐다.
- 해당 run은 `2026-05-07T08:24:16Z`에 `pnpm --filter @grabit/api exec drizzle-kit migrate`에서 실패했고, image build / push / Cloud Run rollout 단계까지 도달하지 못했다.
- `database-url` secret는 `localhost:5432/grapit`를 가리키므로, deploy workflow는 Cloud SQL proxy를 통한 migration 경로를 의도하고 있다.
- PostgreSQL 16 격리 재현 결과, 같은 transaction 안에서 `ALTER TYPE genre ADD VALUE ...` 직후 `UPDATE ... 'ip_popup'::genre`를 실행하면 `unsafe use of new value "ip_popup" of enum type genre`로 실패한다.
- CI가 통과한 이유는 fresh DB가 현재 `0001_motionless_miek.sql`에서 이미 `artist_celebrity` / `ip_popup` 값을 가진 `genre` enum을 만들기 때문이다. 반면 production은 기존 enum 상태에서 `0009_two_event_categories.sql`이 실제로 새 값을 추가해야 하므로 prod-only failure가 발생한다.
- 추가로 `1894d23`는 `apps/api/src/database/migrations/meta/_journal.json`에서 `0009_seed_launch_consent_items`를 제거하고 `0009_two_event_categories` / `0010_collapse_legacy_genres`로 덮어써서, consent seed SQL이 journal에서 orphan 상태다. 이것은 현재 deploy blocker와 별개로 함께 복구해야 한다.

## Plan

1. CLI 증거를 다시 수집해 실패 범위를 잠근다.
   - `gh run view 25484595049 --log-failed`로 GitHub Actions 실패 로그를 재확인한다.
   - 가능하면 `gcloud logging read`로 `2026-05-07T08:24Z` 전후 Cloud SQL / Cloud Run 로그를 조회해 failure가 migration 단계에만 한정되는지 확인한다.
   - 현재 워크스페이스가 merge commit `a3fc3922...`가 아니라 PR source branch tip `bbf8e196...`에 있으므로, patch는 실패 SHA 기준 migration 상태를 의식해서 적용한다.

2. repo를 deployment path 기준으로만 좁게 패치한다.
   - `.github/workflows/deploy.yml`에 pre-migration step을 추가해 `apps/api/src/database/migrations/0009_two_event_categories.sql`만 `pg`/Node로 먼저 실행하고 commit되게 만든다.
   - 그 다음 기존 `drizzle-kit migrate`를 실행하게 해 `0010_collapse_legacy_genres.sql`이 이미 committed 된 enum 값을 사용하도록 바꾼다.
   - 동시에 orphan 된 consent seed는 historical `0009`를 다시 뒤엎지 말고 새 forward-only migration 파일로 복구한다. 예: `apps/api/src/database/migrations/0011_seed_launch_consent_items.sql` 추가 후 `apps/api/src/database/migrations/meta/_journal.json`에 append.
   - `apps/api/src/database/schema/launch-foundation.schema.spec.ts`를 갱신해 launch consent seed migration이 journal에 남아 있는지, category collapse migration과 공존하는지 계약을 고정한다.

3. prod-like 로컬 재현으로 수정 경로를 검증한 뒤 CD 재실행 기준을 만든다.
   - PostgreSQL 16 Docker repro에서
     - single transaction: enum add + immediate update 실패
     - split transactions: enum add commit 후 update 성공
     를 둘 다 남겨 수정 전략이 맞는지 입증한다.
   - `pnpm --filter @grabit/api test -- src/database/schema/launch-foundation.schema.spec.ts`와 추가한 focused migration contract test를 실행한다.
   - `deploy.yml`의 순서가 `Cloud SQL proxy -> pre-enum step -> drizzle-kit migrate`로 유지되는지 grep으로 확인한 뒤, 그 결과를 근거로 CD를 다시 실행한다.
