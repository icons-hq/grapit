<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| QR URL/token -> verify/consume API | Any phone camera can open QR URLs; only server/capability checks may authorize scanner actions. |
| consume transaction -> ticket state | Race conditions can create duplicate entry if update is not conditional and transactional. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-06-QR-REPLAY | R/T | consume transaction | mitigate | Conditional update and duplicate event insertion prevent two successful entries. |
| T-27-06-NORMAL-USER-ACTION | E | controller guards | mitigate | JWT/admin role plus `field.scan.verify`/`field.scan.consume` capabilities gate scanner actions. |
| T-27-06-TAMPER-ENUMERATION | I | verify/consume errors | mitigate | Tampered/unverifiable tokens return redacted rejection and audit evidence without lookup details. |
| T-27-06-OFFLINE-TAMPER | T | online API boundary | transfer | Offline sync is implemented in Plan 27-07; this plan returns online outcomes only. |
| T-27-06-PII-RAW-TOKEN-LEAK | I | scan events/results | mitigate | Results and scan events use masked JTI/redacted token reference only. |
| T-27-06-SCANNER-PRIVILEGE | E | FieldCheckInController | mitigate | Scanner endpoints expose only verify/consume; no settlement/refund/reservation/user/content/security/raw export routes. |
</threat_model>
