| untrusted QR/offline attempts -> PostgreSQL | Scan attempts become durable evidence that drives monitor and settlement. |
| admin audit enum -> sensitive action evidence | Missing audit actions can make scanner/settlement actions unverifiable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-05-QR-REPLAY | R | ticket_scan_events | mitigate | Store duplicate/already-used scan events with prior scan linkage for replay evidence. |
| T-27-05-AUTHZ | E | audit actions | mitigate | Add scan and settlement audit actions so later guards can prove scanner-only limitations and settlement access. |
| T-27-05-TAMPER-LEAK | I | ticket_scan_events metadata | mitigate | Store masked JTI/redacted token reference only; no raw token/JTI/PII columns. |
| T-27-05-OFFLINE-TAMPER | T/R | deviceAttemptId uniqueness | mitigate | Persist device-local attempt id and sync state so server sync is idempotent and auditable. |
| T-27-05-PII-RAW-TOKEN-LEAK | I | schema columns | mitigate | Schema acceptance forbids raw token, full JTI, buyer email, phone, payment key, cookie, and unmasked IP columns. |
| T-27-05-CSV-INJECTION | T | settlement foundation | mitigate | Settlement export implementation remains in Plan 27-09 and must use `safeCsvRows`; schema only supplies joined evidence. |
| T-27-05-MIGRATION-DRIFT | T/D | Drizzle migration | mitigate | Blocking local/test migrate command runs before API verification. |
