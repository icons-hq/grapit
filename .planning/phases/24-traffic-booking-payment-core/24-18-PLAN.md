<gap_diagnosis>
Automated UAT already narrowed the failure to the static load path:
- `PaymentModule` imports `TicketModule`;
- `TicketModule` imports `JobsModule` only to obtain `PG_BOSS` for `QrTicketService`;
- `JobsModule` imports `PaymentModule` so `RefundCancelRetryWorker` can inject `TossPaymentsClient`.

The plan fixes the cycle by separating the shared `PG_BOSS` provider from worker registration. `TicketModule` and `RefundModule` should depend on the provider-only module, while `JobsModule` retains the worker/runtime dependency on `PaymentModule`.
</gap_diagnosis>
