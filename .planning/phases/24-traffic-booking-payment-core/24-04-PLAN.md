<objective>
Implement the server-side admission queue and enforce it on booking mutations.

Purpose: D-01 through D-05 require queue entry to start at `/booking`, but D-02 makes admission an API authorization boundary rather than a cosmetic redirect.
Output: queue module, queue status API, realtime transport, admission guard, and controller wiring.
Decision coverage: D-01: queue admission begins at `/booking`, not event detail or signup. D-02: `lockSeat`, `prepareReservation`, and `confirmPayment` require valid admission at the API boundary. D-03: admission binds `userId + refresh token family/device slot + queue session`. D-04: active, extension, and re-entry grace windows are explicit server-side queue state. D-05: queue APIs expose position, ETA, remaining seats, and auto-entry data for the web flow.
</objective>
