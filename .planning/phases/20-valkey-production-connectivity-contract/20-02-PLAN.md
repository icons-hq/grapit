## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API health -> public callers | `/api/v1/health` exposes service state to Cloud Run and smoke operators. |
| REDIS_CLIENT -> Socket.IO adapter | Redis client capability determines whether multi-instance pub/sub is active. |
| Bootstrap logs -> Cloud Logging/Sentry | Startup failure messages can become production evidence and must stay redacted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Information Disclosure | `redis.health.indicator.ts`, `main.ts` | mitigate | Health metadata is mode/client/configured only; tests assert no `redis://`, auth headers, cookies, JWTs, phone numbers, payment data, or private customer data. |
| T-20-02 | Tampering | `main.ts`, `RedisIoAdapter` | mitigate | Production aborts when Redis pub/sub adapter is not wired, preventing silent default in-process Socket.IO pub/sub. |
| T-20-03 | Denial of Service | Health mode metadata | mitigate | Health exposes the selected client mode so production smoke can compare it with live Memorystore mode and fail mismatch in Plan 20-04. |
| T-20-04 | Tampering | Booking Lua key slots | transfer | This plan does not modify Lua; Plan 20-03 provides cluster-mode Lua coverage. |
| T-20-05 | Integrity | Production lock smoke | transfer | This plan does not mutate inventory; Plan 20-04 requires safe fixture approval and cleanup evidence. |
| T-20-06 | Denial of Service | Cloud Run scaling | transfer | This plan does not scale Cloud Run; Plan 20-04 records pre-state and restore for any temporary scaling. |
</threat_model>
