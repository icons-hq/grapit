<threat_model>
## Trust Boundaries
| Boundary | Description |
|----------|-------------|
| browser UI -> booking/auth/consent APIs | Client state must not be trusted as enforcement but must prevent accidental actions. |
| user consent input -> legal evidence | UI choices must map to immutable API rows. |

## STRIDE Threat Register
| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Elevation of privilege | booking UI/hooks | mitigate | UI blocks handlers while API hard gate remains authoritative. |
| T-23-02 | Tampering | locale display | mitigate | Uses explicit locale messages and no auto redirect. |
| T-23-03 | Repudiation | legal dialogs | mitigate | Itemized rows expose version/language and keep legal text visible before consent. |
| T-23-04 | Spoofing | email verification UI | mitigate | UI calls token-backed API and distinguishes expired/resend/throttled states. |
| T-23-05 | Repudiation | signup consent UI | mitigate | Required consent rows map to immutable API item keys. |
| T-23-06 | Information disclosure | auth UI errors | mitigate | Do not display raw tokens, OTPs, reset links, or full PII in UI states. |
</threat_model>
