# Phase 23 — UI Design Contract

> Visual and interaction contract for Phase 23 Launch Foundation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Boundary

Phase 23 extends existing launch surfaces that later fanmeet phases depend on: booking-disabled affordances, locale routing and selection, localized auth/OTP/email copy, translation review workflow, legal-copy lock, consent capture, and consent audit query. It must not create a separate fanmeet landing page, booking/payment core, queue UI, QR/event-day UI, full admin operations console, WeChat login, PASS identity verification, or mobile app.

Critical scope correction: LINE login is excluded from Phase 23. Do not add a LINE social login button, LINE provider icon, LINE callback copy, or `lineLogin` UI affordance unless roadmap/requirements are explicitly corrected by the user.

Allowed touched surfaces:

| Surface | Contract |
|---------|----------|
| Public fanmeet/event detail shell | Existing page structure; add booking-disabled copy and locale-aware metadata only |
| Global locale affordance | Suggest-never-redirect banner/toast plus explicit locale switcher |
| Auth/signup/reset flows | Existing form density and shadcn form controls; localized copy and email verification states |
| Consent flow | Itemized versioned consent rows, legal dialogs, under-14 block, cross-border required gate |
| Legal/footer surfaces | Existing footer plus required business/legal/contact fields; legal copy stays `ko`/`en` manual |
| Translation review workflow | Existing admin layout, table-first queue, tabs for locales, review/publish states |
| Consent audit query | Existing admin/internal layout, dense filters, table-first evidence display |

Blocked surfaces:

| Surface | Reason |
|---------|--------|
| Separate fanmeet landing page | Out of scope; existing event detail surface is launch surface |
| Booking/payment enablement UI beyond disabled state | Phase 24+ scope and `BOOKING_ENABLED=false` gate |
| Queue, WAF, load-test, QR, refund, settlement UI | Later v2.0 phases |
| New visual brand system or campaign hero | Phase 23 is foundation work; preserve Grabit visual language |
| LINE login UI | Removed by Phase 23 user decision D-13 |

Component contract:

| Need | Component |
|------|-----------|

| Forms and validation | `Form`, `Input`, `Checkbox`, `Select`, `Textarea`, `Label` |
| Consent and legal dialogs | `Dialog`; use `AlertDialog` only for destructive or irreversible actions |

| Mobile admin panel | Existing `Sheet` pattern from admin layout |

Do not add a third-party registry or visual component library in Phase 23.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline status/icon spacing |
| sm | 8px | Checkbox-label gaps, compact row spacing, badge/icon gap |
| md | 16px | Default form, consent row, dialog, and table cell spacing |
| lg | 24px | Auth section spacing, locale banner padding, admin group spacing |
| xl | 32px | Page padding and major content gaps |
| 2xl | 48px | Empty states and large form section separation |
| 3xl | 64px | Page-level spacing only; avoid inside compact admin/auth surfaces |

Exceptions:

- New or touched mobile controls must be at least `44px` high/wide.
- Social login buttons remain `48px` high to match existing provider button pattern.
- Phone country selector remains `44px` high minimum and must not shrink when localized country labels are long.
- Existing shadcn component internals may keep their current dimensions when the component is not otherwise modified.
- Dense admin/audit tables may use 12px vertical cell padding if row height remains at least `44px` for interactive rows.

## Typography

Use exactly these sizes for Phase 23 UI. Do not introduce additional font sizes.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Source: existing `--text-caption: 14px`, `--text-heading: 20px`, `--text-display: 28px`, `text-base`, auth/admin patterns.

Readability rules:

- Korean, English, Thai, Simplified Chinese, and Traditional Chinese strings must fit without horizontal clipping at 320px viewport width.
- Do not scale font size with viewport width.
- Long legal item names, audit IDs, locale tags, and source paths may wrap; never truncate required consent/legal text.
- Admin tables may truncate event title/content snippets only when the detail view exposes full text.
- New Phase 23 text uses only 400 and 600 weights. Existing provider brand buttons may retain current provider styling.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Main background, auth surfaces, dialogs, table/card surfaces |
| Secondary (30%) | `#F5F5F7` | Page background, footer, muted headers, table header bands |
| Accent (10%) | `#6C3CE0` | Primary CTA, focus ring, active locale, selected tab, active admin nav, source links |
| Destructive | `#C62828` | Destructive actions, blocked under-14 state, failed verification, legal-lock violation |

Accent reserved for: primary CTA, focus ring, active locale switcher item, selected tab, active admin navigation, review source link, checked required-consent affordance. Accent must not mean success, warning, legal risk, or disabled booking.

Semantic status colors:

| Status | Surface | Text | Usage |
|--------|---------|------|-------|
| Success / published / verified | `#F0FDF4` | `#15803D` | Reviewed translation published, email verified, consent captured |
| Warning / stale / accepted risk | `#FFFBEB` | `#8B6306` | Translation stale, booking disabled, KST/KRW disclaimer, Phase 22 accepted-risk carry-forward |
| Error / blocked / expired | `#FEF2F2` | `#C62828` | Token expired, under-14 blocked, legal auto-translation blocked, failed verification |
| Informational | `#F3EFFF` | `#6C3CE0` | Locale suggestion, automatic-translation label, traceability note |

Status must not rely on color alone. Every status requires visible text; use lucide icons only where they improve recognition.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `동의하고 계속` |
| Empty state heading | `검수할 항목이 없습니다` |
| Empty state body | `한국어 원문을 저장하면 번역 초안과 검수 항목이 여기에 표시됩니다.` |
| Error state | `정보를 불러오지 못했습니다. 새로고침 후 다시 시도하고, 반복되면 운영자에게 문의하세요.` |
| Destructive confirmation | `none`: Phase 23 must not introduce a destructive user action by default |

Localized booking-disabled copy:

| Locale | Copy |
|--------|------|
| `ko` | `예매는 5월말 오픈 예정입니다` |
| `en` | `Ticket booking opens in late May` |
| `th` | `การจองบัตรจะเปิดปลายเดือนพฤษภาคม` |
| `zh-CN` | `门票预订预计于5月下旬开放` |
| `zh-TW` | `門票預訂預計於5月下旬開放` |

Locale suggestion copy:

| Locale | Copy |
|--------|------|
| `ko` | `다른 언어로 볼까요?` |
| `en` | `View this page in English?` |
| `th` | `ดูหน้านี้เป็นภาษาไทยไหม?` |
| `zh-CN` | `要以简体中文查看此页面吗？` |
| `zh-TW` | `要以繁體中文查看此頁面嗎？` |

Required interaction copy:

| Surface | Copy Contract |
|---------|---------------|
| Automatic translation label | `자동 번역 검수본` / `Reviewed machine translation`; show on all AI-assisted public fanmeet/event content even after review |
| Legal fallback label | Thai and Chinese legal-sensitive copy shows `영문 법적 고지로 확인합니다` or localized equivalent; do not imply native-language legal translation exists |
| Email verification resend | `인증 메일 다시 보내기`; disabled/loading state `다시 보내는 중...`; success `인증 메일을 다시 보냈습니다` |
| Expired email verification | `인증 링크가 만료되었습니다. 새 인증 메일을 요청해주세요.` |
| Under-14 block | `만 14세 미만은 가입할 수 없습니다` |
| Cross-border required refusal | `국외이전 동의가 필요합니다. 동의하지 않으면 가입 또는 팬미팅 예매를 진행할 수 없습니다.` |
| Three-device policy notice | `다른 기기에서 로그인되어 가장 오래된 세션이 종료되었습니다.` |
| LINE exclusion | No visible LINE copy, button, provider loading state, or error mapping |

Copy rules:

- Booking-disabled copy is informational, not a failure. Use warning color only when explaining that booking/payment actions are blocked.
- Legal copy must avoid automated-translation wording for legal-sensitive content. Legal Thai/Chinese users receive English fallback copy.
- All times in event-critical UI must show KST anchor. Example pattern: `2026.07.04 18:00 KST`.
- Currency displays use KRW as source price and estimated conversion as secondary copy with disclaimer. Example pattern: `KRW 110,000 (approx. THB 2,900, exchange rate may change)`.

## Surface Interaction Contract

### Locale Routing And Selection

| Interaction | Contract |
|-------------|----------|
| Korean canonical route | `/` and existing Korean URLs remain prefixless |
| Foreign routes | Use `/en`, `/th`, `/zh-CN`, `/zh-TW`; never rewrite Korean root to prefixed route automatically |
| Detection | Accept-Language/GeoIP may trigger one suggestion toast/banner only |
| Suggestion behavior | User must choose; dismissal persists for the session; no automatic redirect |
| Preference persistence | Anonymous users store cookie; logged-in users store `users.preferred_locale`; UI must expose the currently active locale |
| Locale switcher | Text labels: `한국어`, `English`, `ไทย`, `简体中文`, `繁體中文`; active item uses accent and `aria-current="true"` |
| SEO/supporting metadata | hreflang and sitemap work is not visual but must preserve visible canonical Korean root behavior |

### Booking Disabled Foundation

| State | Contract |
|-------|----------|
| `BOOKING_ENABLED=false` public event page | Primary booking/payment action is disabled or replaced with localized opening copy; no seat lock or payment request can be triggered from UI |
| Disabled action click/tap | If a disabled explanation is needed, show localized toast with booking-disabled copy |
| API hard-gate evidence | UI must not present disabled UI as the only proof; planner/executor must verify backend seat lock, reservation prepare, and payment request/confirm creation paths |
| Visual treatment | Warning/informational badge; never destructive red |

### Auth And Email Verification

| Flow | Contract |
|------|----------|
| Login providers | Keep Kakao, Naver, Google, email; do not add LINE |
| Email verification | Add explicit sent, resend, expired, verified, and error states |
| Resend | Immediate user action is visible, but rate-limit feedback is specific: `잠시 후 다시 요청해주세요` |
| Device policy | If oldest session is revoked on fourth login, show user-visible neutral notice after successful login |
| Errors | Wrong credential, expired token, resend throttled, and system error copy must remain distinguishable |

### Consent And Legal Lock

| Interaction | Contract |
|-------------|----------|
| Consent rows | Itemized rows with required/optional badge, version, language, and `보기` action |
| Required consent gate | Terms/privacy/PIPA/cross-border/PDPA-PIPL required items block continue until checked |
| Marketing consent | Optional and visually separate from required items |
| Select all | Allowed only if required and optional states remain individually inspectable |
| Legal dialogs | `Dialog` with scrollable content, visible title, `sr-only` description if needed, and no nested cards |
| Legal languages | Legal-sensitive copy supports manual `ko` and `en` only; Thai/Chinese locales use English fallback with label |
| Auto-translation lock | Legal, notice, refund, and booking-guide copy cannot enter AI translation queue; blocked attempt displays destructive status text |
| Under-14 | Blocking state is final for this phase; do not offer guardian consent path |

### Translation Review Workflow

| State | Contract |
|-------|----------|
| Draft | Neutral badge `초안`; editable translated text fields per target locale |
| Review | Warning badge `검수 필요`; reviewer sees Korean source beside target locale |
| Published | Success badge `게시됨`; public content shows automatic-translation label |
| Stale | Warning badge `원문 변경됨`; publish action disabled until regenerate/review completes |
| Legal blocked | Error badge `자동 번역 불가`; show reason and manual `ko/en` path |
| Empty | Use empty state copy from this spec |
| Loading | `Skeleton` rows with stable table height |
| Error | `role="alert"` and retry action |

Workflow layout:

1. Summary filters: content type, locale, status, updated date.
2. Table queue: source title, content type, locale, status, updated at, reviewer, action.
3. Detail/review panel or route: Korean source left/top, target draft right/below, review actions at bottom.
4. Mobile: stack source before target and keep publish CTA sticky only if it does not cover content.

### Consent Audit Query

| Interaction | Contract |
|-------------|----------|
| Filters | User, item, version, language, timestamp range, IP |
| Results | Dense table with item, version, language, user, IP, timestamp, source flow |
| Privacy | Mask email/phone by default; reveal raw PII only if an existing admin permission pattern explicitly allows it |
| Row activation | Click, `Enter`, and `Space` open detail, matching existing admin table behavior |
| Export | Not required in Phase 23 unless planner explicitly scopes it; do not imply settlement/export capability |

## Accessibility And Readability

| Area | Contract |
|------|----------|
| Keyboard | All locale, consent, translation, and audit controls must be reachable and operable by keyboard |
| Focus | Use existing `focus-visible:ring-ring` / `focus-visible:ring-primary`; never suppress focus outlines |
| Screen reader status | Errors use `role="alert"`; resend/saved/published status uses `aria-live="polite"` |
| Language | Set document/route language correctly for each locale; mixed legal fallback content must identify English content textually |
| Color contrast | Body text on white uses `#1A1A2E`; muted text uses `#6B6B7B` only on white or very light surfaces |
| Touch target | New/touched mobile controls must be at least `44px` |
| Motion | Respect `prefers-reduced-motion`; no new decorative motion |
| Tables | Headers use `scope="col"`; horizontal overflow is allowed for dense audit data |
| PII | Audit and evidence views mask phone, email, token, OTP, reset link, IP where not needed for the visible task |
