# Phase 25 — UI Design Contract

> Visual and interaction contract for Phase 25 Admin Operations Console. Generated by gsd-ui-researcher and pending gsd-ui-checker verification.

---

## Phase UI Boundary

Phase 25 completes the internal admin operations console needed for M1 advertising open and the subsequent ticketing/CS run. It must extend the existing Grabit admin shell and dense operations pattern instead of creating a separate tool, wizard-first flow, or marketing-style redesign.

Allowed touched surfaces:

| Surface | Contract |
|---------|----------|
| Event registration and publish | Extend the existing performance form into a multilingual operations surface with locale tabs, publish review, sale-setting visibility, and publish confirmation |
| Unified operations inbox | One operator-facing inbox for unanswered Q&A, CS tickets, refund disputes, review requests, urgent notices, SLA state, and escalation priority |
| Banner, notice, FAQ, and Q&A management | Reuse table-plus-detail and form-plus-preview patterns already used in admin pages |
| Reservation operations and export | Keep reservation-specific actions in the reservation detail modal, and move seat-centric actions into a dedicated seat operations panel |
| Security and audit surfaces | Show allowlist/access state, accepted-risk MFA status, and sensitive-action audit evidence with masked diffs |

Blocked surfaces:

| Surface | Reason |
|---------|--------|
| `BOOKING_ENABLED=true`, Toss live cutover, and production canary controls | Phase 26 scope |
| Field QR scanning, entry monitor, and offline scan sync | Phase 27 scope |
| Settlement export and post-event retrospective UI | Phase 27 scope |
| New public brand palette, dark mode, or public-shell redesign | Preserve current Grabit visual language |
| Mandatory multi-step human approval bureaucracy | Phase 25 must stay admin-led and fast per D-01/D-02 |

Scope correction:

- Phase 25 multilingual admin content follows the launch contract from roadmap/context: `ko`, `en`, `th`, `zh-CN`, and `zh-TW`.
- If inherited code still exposes `ja` in some older admin translation paths, treat that as implementation drift to reconcile in planning. Do not broaden Phase 25 UI to a sixth locale.

Source: `.planning/ROADMAP.md`, `.planning/REQUIREMENTS.md`, `.planning/phases/25-admin-operations-console/25-CONTEXT.md`, `.planning/phases/23-launch-foundation/23-UI-SPEC.md`, `.planning/phases/24-traffic-booking-payment-core/24-UI-SPEC.md`, current `apps/web/app/admin/*`, and `apps/web/components/admin/*`.

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | Local `apps/web/components/ui` primitives built on Radix and Tailwind CSS v4 tokens |
| Icon library | `lucide-react`; use only for navigation, severity, state, and action clarity |
| Font | Pretendard via `next/font/local`, fallback `-apple-system`, `"Malgun Gothic"`, `sans-serif` |

Baseline contract:

- Do not initialize shadcn during Phase 25.
- Reuse the existing local `Button`, `Input`, `Select`, `Textarea`, `Table`, `Badge`, `Dialog`, `AlertDialog`, `Sheet`, `Tabs`, `Card`, `Skeleton`, and `Tooltip` primitives as the baseline design system.
- Keep the current admin shell structure: white sidebar, sticky white header, light-gray workspace background, white content cards, dense tables, and restrained icon use.

Component contract:

| Need | Component |
|------|-----------|
| Admin shell and mobile nav | Existing `AdminSidebar`, `Sheet`, `Button` |
| Dense queue, audit, export, and inbox lists | `Table`, `Badge`, `Input`, `Select`, `Skeleton`, `ScrollArea` |
| Section summaries and KPI panels | `Card` or existing stat-card pattern |
| Sensitive confirmation without structured input | `AlertDialog` |
| Sensitive confirmation with reason, diff, or filter summary | `Dialog` with required `Textarea` or read-only summary block |
| Locale/content workflow | `Tabs`, `Badge`, `Textarea`, `Button`, `Separator` |
| Inline failure or access-denied states | Full-width `role="alert"` block inside the card or table container |
| Transient success feedback | `sonner` toast only after the blocking action has already completed |

Do not add any third-party registry, alternate component library, or custom visual token system in this phase.

## Layout Contract

### Admin Shell

| Area | Contract |
|------|----------|
| Sidebar | Keep the current 240px white sidebar, grouped into overview, event/content, operations, and security/audit concerns |
| Header | Sticky white header with current user name, logout, and mobile menu only; no marketing banner or public-brand hero |
| Workspace | `#F5F5F7` page background with white cards and tables as primary working surfaces |
| Page title row | One display title on the left, one primary CTA on the right, secondary filters below |

### Desktop/Mobile Density

| Breakpoint | Contract |
|------------|----------|
| `xl` and above | Prefer table plus detail-pane or table plus modal workflows for inbox, audit, and translation-like review surfaces |
| `md` to `lg` | Stack filter bars above the table; keep action bars sticky only when the form is long |
| Mobile | Collapse sidebar into `Sheet`; detail views open as full-height `Dialog` or `Sheet`, not cramped inline accordions |

### Information Order

1. Severity or required action.
2. Subject/resource summary.
3. SLA or publish state.
4. Assignee/role/category metadata.
5. Secondary context such as locale, zone/floor, method, or timestamps.

The first screen of any Phase 25 surface must tell the operator what needs attention now. Do not force operators to open detail screens to find overdue or escalated work.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline icon gaps, compact badge padding, micro separators |
| sm | 8px | Filter-control gaps, inline metadata spacing, dialog footer button gaps |
| md | 16px | Default form spacing, card padding, section spacing inside a surface |
| lg | 24px | Page-section separation, form group separation, split-panel spacing |
| xl | 32px | Major content gaps, dashboard section spacing |
| 2xl | 48px | Large empty states, security/audit overview separation |
| 3xl | 64px | Page-level top/bottom spacing only |

Exceptions:

- New or touched mobile controls must be at least `44px` high or wide.
- Primary publish, export, save, and destructive confirm buttons stay `48px` high.
- Dense admin tables may use `12px` vertical cell padding only if the interactive row height remains at least `44px`; clickable primary rows should target approximately `52px` as in the existing performance table.
- Sidebar items and compact desktop filters may be `40px` high on desktop, but must remain `44px` minimum on touch layouts.
- Long forms may use sticky footers only when the footer preserves `16px` vertical padding and does not cover validation or audit summary content.

Source: inherited from prior Phase 23/24 contracts and confirmed by `apps/web/app/globals.css` plus current admin component density.

## Typography

Use exactly these four roles for new or touched Phase 25 UI. Do not add a new display scale.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 | 1.5 |
| Label | 14px | 600 | 1.4 |
| Heading | 20px | 600 | 1.2 |
| Display | 28px | 600 | 1.2 |

Readability rules:

- Use `Display` only for top-level page titles such as dashboard, event publish, or security/audit landing views.
- Use `Heading` for card titles, modal titles, and detail-pane titles.
- Use `Label` for filter labels, table headers, status chips, SLA chips, inline reasons, and action buttons.
- Use `Body` for event descriptions, support answers, audit detail text, and operator guidance copy.
- Do not introduce new `12px` helper copy on touched Phase 25 surfaces. Dense secondary metadata should use the `Label` role instead.
- New authored text should use only weights `400` and `600`. Existing untouched local primitive internals may keep their current default styling, but Phase 25-specific copy must not introduce additional weights.
- Overdue, security, refund, export, and seat-operation copy must never drop below `14px`.

Source: inherited core scale from Phase 23/24 with Phase 25-specific density guidance based on current admin pages.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#FFFFFF` | Content cards, dialogs, tables, detail panes, sidebar/header surfaces |
| Secondary (30%) | `#F5F5F7` | Workspace background, table headers, muted form bands, secondary cards |
| Accent (10%) | `#6C3CE0` | Primary CTA, focus ring, active sidebar item, selected tab, selected inbox row, active filter state |
| Destructive | `#C62828` | Overdue SLA, access denied, destructive confirms, blocking security or export warnings |

Accent reserved for: primary publish/save CTA, active sidebar item, selected locale tab, selected inbox or audit row, active filter state, focus ring, and reviewed/publishable workflow emphasis. Accent must not be used for overdue SLA, escalated fraud/payment risk, or destructive seat/export actions.

Phase-specific state colors:

| State | Surface | Text | Usage |
|-------|---------|------|-------|
| Success / published / resolved | `#F0FDF4` | `#15803D` | Published event, answered CS, completed export, successful seat reactivation |
| Warning / review / due soon / accepted risk | `#FFFBEB` | `#8B6306` | Review-needed content, soon-due SLA, deferred MFA notice, publish caution |
| Error / overdue / escalated / denied | `#FEF2F2` | `#C62828` | Overdue SLA, escalated payment/refund risk, access denial, destructive guardrail |
| Informational / audit trace | `#F3EFFF` | `#6C3CE0` | Audit context, publish summary, allowlist exception evidence, selected review state |
| Neutral inactive / disabled | `#F5F5F7` | `#6B6B7B` | Disabled seats, archived notices, unavailable actions, background metadata |

Color rules:

- SLA urgency is color-coded only after the text label is visible. Show text such as `마감 임박`, `기한 초과`, or `즉시 확인` with the chip.
- Access-denied, overdue, and raw-PII export warnings use destructive red. General pending work does not.
- MFA is deferred in this phase; do not show green security-complete states for admin auth. Use warning amber with explicit accepted-risk copy.
- Status must never rely on color alone. Every badge or row highlight needs text and, where helpful, an icon.

Source: `apps/web/app/globals.css`, existing admin badges, and D-06 through D-15 in `25-CONTEXT.md`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `이벤트 게시하기` |
| Empty state heading | `처리할 운영 항목이 없습니다` |
| Empty state body | `미답변 문의, 검토 요청, 환불 분쟁이 생기면 여기에 표시됩니다. 필터를 조정하거나 새 공지 또는 FAQ를 등록하세요.` |
| Error state | `운영 데이터를 불러오지 못했습니다. 새로고침 후 다시 시도하고, 반복되면 접근 권한 또는 API 상태를 확인하세요.` |
| Destructive confirmation | `좌석 비활성화`: `이 좌석을 비활성화하면 판매 가능 수량이 즉시 변경됩니다. 사유를 입력하고 변경 내용을 확인한 뒤 진행하세요.` |

Critical copy set:

| Surface | Copy Contract |
|---------|---------------|
| Publish confirmation | `이 이벤트를 게시하시겠습니까?` |
| Publish confirmation body | `게시 후 공개 화면과 판매 설정이 운영 기준으로 반영됩니다. 변경된 필드와 판매 일정을 확인한 뒤 진행하세요.` |
| Operations inbox due soon | `24시간 SLA 마감이 가까워지고 있습니다` |
| Operations inbox overdue | `24시간 SLA를 초과했습니다. 즉시 확인해주세요` |
| Escalated risk badge | `즉시 확인` |
| Escalated categories | `결제 오류`, `환불 미처리`, `부정 이용 의심`, `가입 실패` |
| Raw CSV export confirmation | `예약자 원본 CSV를 내보내시겠습니까?` |
| Raw CSV export body | `개인정보가 포함됩니다. 필터와 사유를 확인한 뒤 내보내세요.` |
| Seat reactivation confirmation | `좌석을 다시 판매 가능 상태로 변경하시겠습니까?` |
| Immediate cancelled-seat open | `이 취소 좌석을 지금 즉시 개방하시겠습니까?` |
| Deferred MFA notice | `MFA는 아직 적용되지 않았습니다. 현재는 IP allowlist와 audit monitoring으로 운영합니다.` |
| Translation-use label | Reuse Phase 23 label `자동 번역 검수본`; do not invent a new assisted-translation label |

Copy rules:

- Use plain operational Korean. Avoid promotional or reassuring marketing tone inside admin surfaces.
- Status copy must explain the next action, not only the problem. Example: overdue SLA copy tells the operator to act now.
- Thai and Chinese support content may use assisted translation, but Korean and English remain manual operator-controlled sources.
- Public-facing multilingual support content created from the admin must keep the reviewed machine-translation indication where Phase 23 already requires it.
- Do not imply MFA is already protecting admin access. The UI must surface the deferment honestly.

## Surface Interaction Contract

### Event Registration And Publish

| Interaction | Contract |
|-------------|----------|
| Form structure | Keep the existing form-led pattern; extend it with grouped sections for core info, localized content, seating/pricing, sale settings, and publish review |
| Locale tabs | Order: `ko`, `en`, `th`, `zh-CN`, `zh-TW`; pin `ko` and `en` first, show translation-state badges on the remaining locale tabs |
| Publish state model | Visible lifecycle stays at four states maximum: `draft`, `review`, `publish-ready`, `published` |
| Publish ownership | Publish remains fast and admin-led; do not force a chained reviewer-to-approver handoff flow |
| Final publish | Publish requires a confirmation modal with changed-field summary and audit-trigger language before commit |
| Missing content | Missing required Korean or English content blocks publish; missing Thai/Chinese content may remain review-state only if planner confirms assisted-translation flow satisfies the requirement |

Event-form rules:

- Keep the existing `PerformanceForm` as the structural baseline; do not replace it with a wizard.
- Show locale state per tab instead of hiding incomplete locales behind a secondary screen.
- Put the main publish or save action in a stable top-right or sticky footer position; do not move the primary CTA as the operator scrolls.
- Show sale windows, payment-method visibility, ticket-limit policy, and seat-map count in the publish review summary before confirmation.

### RBAC And Permission Affordances

| Interaction | Contract |
|-------------|----------|
| Route-level access | Non-admin or unauthorized roles land on an explicit access-denied state, not a blank page |
| Action-level permissions | Role-restricted actions stay visible but disabled with a reason tooltip unless showing the action itself would leak sensitive scope |
| Role language | Use human-readable role chips such as `운영자`, `검토자`, `승인자`, `재무` |
| Scope correction | Roles define capability bundles, not a mandatory serial approval ceremony |

Permission rules:

- Use disabled affordances and tooltips for predictable workflows such as export, publish, or refund/admin refund.
- Hide only security-sensitive route entries that would reveal protected infrastructure or permission-change scope.
- Never allow the UI to suggest an action succeeded when the role lacks permission; failures must produce inline or toast feedback tied to the action.

### Unified Operations Inbox

| Interaction | Contract |
|-------------|----------|
| Default surface | One unified inbox is the operator default, not separate silo-first screens |
| Sort order | Sort by severity first, then SLA urgency, then creation time |
| Required row data | Category, title/subject, locale, masked requester, assignee or queue, SLA chip, and escalation state |
| Layout | Desktop uses table plus detail pane or modal; mobile uses a stacked list plus full-height detail sheet |
| SLA visual states | Neutral when newly opened, amber when close to 24h, red when overdue |
| Escalated items | Auto-escalated risk categories start with a red `즉시 확인` chip and stay pinned above non-escalated items |

Inbox rules:

- Q&A, CS, refund disputes, notice follow-up, and review requests must feel like one work queue with filters, not five independent admin mini-apps.
- Operators should be able to answer, escalate, or reassign without losing the current filter context.
- FAQ and notice authoring can live in adjacent routes, but unresolved work from those routes must still appear in the unified inbox when action is required.

### Seat Operations And Reservation Export

| Interaction | Contract |
|-------------|----------|
| Reservation-specific action | Cancelled-seat immediate open stays inside the reservation detail modal |
| Seat-centric action | Seat disable/reactivate/history lives in a dedicated seat operations panel |
| Reason capture | Disable, reactivate, immediate open, admin refund, and raw CSV export require a reason before the confirm action becomes enabled |
| Export filters | Show all seven filters before export: event, tier, zone/floor, reservation status, domestic/overseas, payment method, and date range |
| Confirmation | Confirm dialogs must echo the filter summary or changed seat/resource summary before execution |
| Result feedback | Post-action toast must restate what changed, not only that the request succeeded |

Seat/export rules:

- Seat-state tables must show zone/floor, tier, seat key or label, current state, last changed at/by, and latest reason snippet.
- Immediate cancelled-seat open is a high-risk operational override and must never be a silent icon toggle.
- Export UI must warn about raw PII before the operator clicks the final action, not after the file is generated.

### Security And Audit

| Interaction | Contract |
|-------------|----------|
| MFA status | Show a visible amber deferred-security note; do not present MFA as completed |
| IP allowlist | Surface current allowlist or access-exception status with timestamps and evidence context |
| Audit query | Use dense filters above a table; row click opens a masked diff detail view |
| Audit row data | Actor, action, resource, status, time, IP, reason, and changed-field summary |
| Diff detail | Show before/after field-level changes only where safe; mask PII, secrets, tokens, raw OTPs, and credentials |
| Immutability | Audit logs are read-only in the UI; no inline edit or delete affordance |

Security/audit rules:

- Access-denied or allowlist-exception events should use inline alert bands above the table or detail card.
- The audit experience must be readable by operators who are tracing a specific action, not only by developers reading raw JSON.
- Raw exported CSV values themselves must never be copied into audit previews or reason history.
