# 정산 원장 대조와 마감 증거

재무 capability `settlement.export`가 필요하다. 입장·특전 지급·권한 관리는 포함하지 않는다. 이 절차는 PG 취소나 DB 보정 명령이 아니다.

## 조회

PG 자료를 포함하는 조회와 export는 시작·종료일 포함 최대 31일이다. 긴 기간은 월별 또는 31일 이하로 나누어 요청한다. 이 상한은 공유 계약과 API에서도 검증하며, 초과 요청은 공급자를 호출하기 전에 400으로 거절한다. 내부 원장만 조회하는 기간에는 이 PG 제한을 적용하지 않는다.

1. 정산 화면에서 공연·회차(또는 전체 회차), 조회 시작/종료일과 원장 기준 시각을 고른다. 모두 KST다.
2. 승인일 기준은 해당 기간 승인된 거래를, 취소 기준은 완료 취소일(처리 중이면 요청일)이 해당 기간인 거래를 선택한다. 원 주문/환불 누계는 선택된 거래의 기준 시각까지의 누적액이다. 월별 누적액을 다시 더하지 않는다. 기간 내 승인·환불 지표는 해당 기간 움직임만 센다.
3. `원장 조회`로 저장 원장을 읽는다. 원 주문과 저장 결제액, 확정 환불과 처리 중 요청, 유효 티켓, 취소 수수료와 서비스 수수료를 구분한다. 금액 증거가 없으면 미확인이다. 취소 거절·복원 전 시점은 보존된 취소 견적/이력으로 읽는다.
4. PG 청구·취소는 저장된 승인/취소 증거다. KRW minor unit은 1원, USD는 1센트다. 통화가 다른 금액을 더하지 않는다. 청구에서 확정 취소를 뺀 값은 계산 잔액이며 정산 지급액이 아니다.
5. `PG 자료까지 조회`는 별도 정산 매출일 또는 지급일 기준으로 같은 공연/회차의 모든 승인 거래를 대조한다. 전액 취소도 포함한다. 정산 날짜는 거래 승인일과 다를 수 있고, 현재 PG 응답은 과거 `asOf` 조회 결과를 복원한 자료가 아니다. PG 조회 시각을 함께 보관한다.

## 내보내기와 검산

자료 종류와 구체적인 사유를 입력한다. 현재 표시된 필터와 기준 시각으로 다시 읽고 CSV 생성 시각/PG 조회 시각을 기록한다. 조건을 바꾸면 기존 금액과 내보내기는 숨겨지므로 새로 조회한다.

- 결제·환불 CSV: 한 Payment가 한 행이다. 원 주문·저장 결제액·환불·유효 티켓·수수료와 원본 주문/결제 ID를 대조한다.
- 좌석·입장 CSV: 한 Ticket Item이 한 행이다. 금액/입장/취소 요청·완료 시각을 읽는다. 주문 전체 금액을 좌석마다 반복 합산하지 않는다. 미래 공연의 미입장을 노쇼로 확정하지 않는다.
- PG CSV: 한 정산 transaction이 한 행이다. 승인/취소는 부호를 유지하며 통화별 `amount_minor`, `deductions_minor`, `payout_minor`를 대조한다. PG 조회 일부/전체 실패·미조회 상태에서는 내보낼 수 없다.
- 첫 `record_type=scope` 행은 조회 범위·시간대·상태 기록이며 금액 합산 대상이 아니다. `payment`, `ticket`, `provider_settlement` 행만 해당 단위로 계산한다. 빈 금액 칸은 미확인이며 0으로 채우지 않는다. 성공한 0건 파일에도 scope 기록이 남는다.
- 연락처·구매자 이름·결제 키·QR 원문은 내보내지 않는다. 파일에는 거래 식별자가 있으므로 재무 담당 범위 안에서 보관한다. 내보내기 사유/필터/행 수는 감사 로그에 남는다.

## 차이 기록과 마감

다음 항목을 별도 대조 문서에 남긴다: 공연/회차, 기간 기준/KST/asOf, CSV 생성 시각, 통화별 사이트 원장액, PG 거래/정산 원본과 조회 시각, 은행 거래 내역의 입금일/금액/참조번호, 차이 금액과 원인, 미확인 항목, 담당자/검토자/확인일.

순서는 **원장 → PG 자료 → 은행 증빙 → 차이 원인·미해결 → 담당자 확정**이다. 서비스는 은행 증빙을 수집하거나 회계 마감 승인하지 않으므로 `은행 실입금 미확인 · 마감 미완료`를 유지한다. 정산 지급일이 지나거나 PG가 완료 상태라고 해서 실제 입금·카드사 환불 반영을 확정하지 않는다. 재대조는 이전 자료를 덮어쓰지 말고 사유와 새 파일을 추가한다.

## 전환·복귀

새 화면은 `/admin/settlement/ledger`와 `/ledger/export`를 사용한다. 구 summary/reconciliation/export API는 410과 전환 안내를 반환한다. API/Web을 함께 배포하고 정산 화면을 새로고침한다. 외부 스크립트가 구 API를 사용하면 기준 시각·날짜 기준·nullable 금액을 새 계약으로 옮긴 후 사용한다. 구 CSV와 새 CSV를 같은 정의로 합치지 않는다. 복귀는 API/Web 이전 revision을 함께 사용하며 원장 DB는 수정하지 않는다.

실제 상점 PG 정산·은행 입금 대조는 #214/#223 증거를 요구한다. 격리 fixture, 모의 provider, 브라우저 CSV 검산은 실제 입금 검증을 대신하지 않는다.

과거 좌석 취소 준비가 내부 실패로 보상 복구되어 command/견적이 지워진 경우, 기준 시각 이후 수정된 티켓의 과거 상태를 active나 0원으로 복원하지 않는다. 관련 금액은 미확인으로 유지한다. 취소일을 확정할 수 없는 거래는 취소일 조회에서 대조 후보로 포함하며 경고한다. 이 보수적인 판정은 입장 등 다른 변경으로 수정 시각이 갱신된 과거 티켓에도 적용될 수 있다. 현재 시각 조회 또는 보존된 원본 증거로 재대조한다.
