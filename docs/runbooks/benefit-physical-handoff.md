# 현장 특전 실물 인수와 지급 대조

이 양식은 공연·회차별로 복사해 실제 담당자가 작성한다. 빈칸은 미확인이다. 시스템의 특전 권리는 지급 의무를 나타내며 실물 입고나 실제 지급의 증거가 아니다.

2026-09-18 운영자 확인: 지난 Girl Rules 사인 포스터 부족은 현장에서 발생했고 입고·지급·잔량 기록이 남아 있지 않다. 과거 부족 수량이나 원인은 재구성할 수 없으며 임의 수치로 채우지 않는다.

## 행사 전 인수

| 확인 항목 | 실제 입력 |
| --- | --- |
| 공연 / 회차 / 지급 장소 | |
| 기준 시각 / 권리 export 버전 / 발표표 버전 | |
| 입고 확인 담당자 / 지급 책임자 / 마감 대조 담당자 | |
| 공급자 인수증 / 추가 보상 승인 자료 위치 | |
| 통신 장애 대기 접수 담당자 / 기록의 보관 위치 | |

1. 혜택 관리에서 대상 회차와 최신 권리·발표표를 확인한다. 기본, 추첨, 추가 보상과 취소된 권리를 구분한다. 유효 권리 수는 `지급 대상 내려받기`의 `State=active`(미수령)와 `redeemed`(수령)로 센다. 실행 기록의 live run `CSV`도 내려받는 시점의 현재 상태를 `State`에, 비활성 사유(`replaced_by_live_run`, `rollback_to_previous_run`, 취소 등)를 `Inactive Reason`에 보여준다. test run CSV는 티켓에 붙지 않은 모의 결과다.
   - `실제 적용`은 저장된 설정으로만 실행한다. 화면에 저장되지 않은 변경이 있으면 버튼이 막히므로 먼저 `설정 저장`을 하고, 확인 창에 표시된 회차·한정 특전 수량·대상 등급을 대조한 뒤 확정한다.
   - `함께 배정하지 않을 한정 특전`은 한정 특전끼리만 적용된다. 기본 포함 특전에는 설정할 수 없다(과거에 저장된 그런 규칙이 있으면 실행이 거절되므로 설정을 다시 저장한다).
   - 판매 오픈·결제 피크 중에는 설정 저장·실제 적용·되돌리기를 하지 않는다. 결제와 겹치면 `잠시 후 다시 시도` 오류로 실패하며, 진행되면 그 회차 발권이 잠시 대기한다.
2. 권리 identity를 실제 품목에 연결하고 권리 하나당 지급 수량을 정한다. 이름이 비슷한 사인/일반 포스터를 임의로 합치거나, 같은 실물을 가리키는 권리를 이중 합산하지 않는다.
3. 인수증과 실제 수량을 두 사람이 대조한다. 불량·격리품은 지급 가능한 재고에서 제외한다. 필요 수량과 부족분을 확정하기 전 지급 완료로 표시하지 않는다.

## 지급 시 기록

QR 입장 처리와 특전 수령은 별개다. 전면 개편 적용 후 새 입장은 해당 QR의 좌석 한 장만 처리하며, 실물은 해당 티켓의 특전 권리를 확인하고 권리별 수령을 확정해야 한다. 과거 일괄 입장 기록은 유지한다. 구매자에게 보이는 QR을 직원 단말로 읽고 품목을 대조한 뒤 한 번만 지급한다.

- 온라인 수령 결과가 성공한 것을 확인하고 실물을 건넨다. `이미 수령`이면 다시 지급하지 않는다.
- 전산 결과가 불명확하면 재조회 후 처리한다. 담당 직원의 추정으로 성공 건을 삭제하거나 권리를 다시 만들지 않는다.
- 통신 장애 중에는 실물 지급을 보류한다. 지류는 대기 접수와 보관 물품 확인에만 사용한다. 현재 특전 수령 API는 원본 QR token을 요구하며 입장용 offline sync는 특전 수령을 지원하지 않는다. 권리/티켓 ID만으로 사후 수령 확정이 가능하다고 가정하지 않는다. 통신 복구 후 구매자의 QR을 다시 읽고 서버 수령 성공을 확인한 다음 지급한다.
- 반납·추가 보상은 새 이동 행으로 기록한다. 교환은 같은 교환 묶음 번호로 반환받은 SKU의 `반환` 행과 새로 내준 SKU의 `지급` 행을 각각 기록한다. 같은 SKU 교환도 두 행으로 남기며 모든 수량은 양수로 기록한다. 기존 지급 기록을 지우거나 수령 상태를 임의 초기화하지 않는다.

| 시각 | 권리 / 티켓 내부 참조 | 품목 | 이동 구분(지급·반환·손실) | 수량 | 전산 결과 / 접수·교환 묶음 번호 | 담당자 | 예외 근거 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

연락처·전체 QR token·결제 key를 이 대장에 적지 않는다. 티켓/권리 식별자가 필요한 원본은 운영자만 접근할 수 있는 보관 위치를 사용한다.

## 마감 인수

품목마다 `기초 재고 + 입고 + 반환 - 실제 지급 - 손실 = 계산 잔량`을 계산하고 실사 잔량과 대조한다. QR 수령 수와 실물 지급 수량의 단위가 일치하는지 확인한다. 교환의 반환 행은 `반환`에, 교환의 지급 행은 `실제 지급`에 포함한다. 대기 접수는 지급 수량에 포함하지 않는다.

| 품목 | 계산 잔량 | 실사 잔량 | 차이 | 전산 수령 수 | 미처리 대기 접수 수 | 차이 원인 / 미확인 사항 | 확인자 / 인수 시각 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | |

차이가 남으면 미확인으로 기록하고 관련 인수증·지급 행·전산 수령 이력을 보존한다. 사람 수, 입장 처리 수, 특전 권리 수를 같은 수량으로 간주하지 않는다.
