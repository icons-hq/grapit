# 티켓과 함께 구매하는 한정 애드온

애드온은 좌석 선택 화면에서 고르고 같은 주문으로 결제한다. 티켓 구매 후 별도 주문하는 상품이 아니다. 티켓 1장에 상품별 1개를 연결하며, 사용자가 보낸 가격·잔여 수량은 신뢰하지 않는다.

## 재고와 결제 계약

- PostgreSQL `booking_addons`가 상품·가격·수량·대상 등급의 기준이다. `booking_addon_holds`는 구매자·좌석·상품별 한 단위의 선점과 주문 연결을 보존한다.
- 선택 시 상품 행을 `FOR UPDATE`로 잠그고 재고를 계산한다. 좌석 소유권·인증·대기열·판매 가능 여부·좌석 등급을 확인한다. 선점 만료 시각은 좌석 선점을 따른다.
- 복수 상품은 ID 순서로 잠근다. 주문 준비 트랜잭션에서 정확히 요청한 선점만 예약에 연결하고 애드온 총액을 저장한다. 같은 주문 ID의 재요청은 좌석·애드온·총액이 같아야 한다.
- 미결제 선점은 만료·선택 해제·좌석 해제로 반환한다. `PENDING_PAYMENT`에 연결된 수량은 원래 선점 TTL이 지나도 유지하며, 기존 결제 만료·PG 확인·보상 흐름이 주문을 종료한 뒤 반환한다. 승인 결과를 모르는 주문의 재고를 시간만 보고 재판매하지 않는다.
- 동기 결제 승인 및 비동기 DONE 모두 티켓·결제·유료 특전 발급을 한 트랜잭션으로 처리한다. 지연 승인 시 다른 주문이 이미 사용한 재고는 다시 발급하지 않고 기존 보상 취소 경로로 처리한다.
- `reservations.addon_amount`와 좌석별 `ticket_items.addon_amount`에 구매 금액을 보존한다. 유료 특전은 `source=purchase`, `kind=paid`이며 기존 좌석 QR로 수령한다. 기존 무료·추첨 특전과 별개다.

## 실시간 동기화

`addon-stock-changed`는 상품별 잔여·선점·판매 수량을 Socket.IO/Valkey로 전파한다. 구매자, 좌석, 주문 및 개인별 선택은 포함하지 않는다. 일반 수량 변경마다 모든 브라우저가 다시 API를 호출하지 않는다.

DB statement timestamp의 마이크로초 `revision`으로 서로 다른 인스턴스의 역순 이벤트를 무시한다. 늦게 도착한 GET 응답도 더 최신 수량을 덮어쓰지 않는다. 개인별 선택은 인증된 API 응답으로만 동기화한다. API와 background worker 모두 결제·좌석 해제·취소 후 수량 변경을 전파한다.

접속·재접속·화면 복귀·만료 시 재조회하며, 연결 중 5초/연결 끊김 시 1.5초 polling으로 유실을 복구한다. 이 수치는 유실 복구 간격이며 정상 이벤트의 지연 목표가 아니다. 결제 확인 화면으로 넘어가기 직전에 좌석과 애드온 선점을 다시 읽는다. 실제 구매 허용 여부는 항상 서버의 트랜잭션 검사로 정한다.

## 취소와 정산

애드온은 연결된 좌석과 함께 취소한다. 기존 공연 취소 수수료 정책을 티켓 가격과 애드온 합계에 적용한다. 애드온에 별도 예매 수수료를 추가하지 않는다. 취소 요청 중에는 재고를 유지하며 PG 취소 확정 후 반환한다. 취소가 거절되면 구매한 특전도 복구하고, 이후 상품 판매 중단 여부와 무관하게 이미 결제한 권리를 보존한다. 이미 수령한 특전은 기존 취소 제한을 따른다.

관리자 매출·등급별 매출·정산 원장 잔액에는 애드온 금액을 포함한다. 예매 CSV는 기존 열 순서를 유지하고 마지막에 `Add-on Amount`를 추가한다. 정산 티켓 CSV에는 `addon_krw`를 별도로 제공한다. 유료 특전도 기존 특전 보유자 CSV에 `purchase/paid`로 포함한다.

## 등록 API와 제한

- `PUT /api/v1/admin/showtimes/:showtimeId/addons`: `event.write` 권한. `identity`로 upsert하며 감사 로그를 남긴다. 본문은 `bookingAddonDefinitionSchema`를 따른다.
- `GET /api/v1/booking/addons/:showtimeId`: 인증 필요. 비공개 공연은 전체 관리자만 조회할 수 있다.
- `PUT /api/v1/booking/addons/holds`: `{ showtimeId, addonId, seatKey, selected }`. 실제 좌석 선점 및 예매 권한이 필요하다.

재고를 현재 선점·판매 수량보다 줄일 수 없다. 수량이 소비 중일 때 가격이나 대상 등급을 바꿀 수 없다. 대상 등급은 공연 가격 등급에 존재해야 한다. 판매 중단은 `active=false`로 처리하며, 이미 연결된 주문·특전·선점 기록을 직접 삭제하지 않는다.

판매 중단 시 구매자의 기존 선택은 해제할 수 있도록 표시하고, 해제 전에는 다음 단계로 진행하지 않는다. 예매·운영 이력이 없는 공연이나 회차를 기존 관리자 삭제 경로로 제거할 때만 미결제 선점과 상품 설정을 같은 트랜잭션에서 정리한다. 주문에 연결된 선점은 삭제하지 않으며 FK가 구매 기록 삭제를 막는다.

## 배포 및 복구

운영 반영은 승인된 Deploy workflow로 migration `0052_paid_booking_addons.sql`과 API/Web/background-worker 코드를 함께 배포한다. 이 migration은 신규 테이블·금액 열·enum 값을 추가하며 기존 주문의 애드온 금액은 0이다.

운영 승인 후 비공개 공연에서 관리자 화면, 일반 사용자 차단, 두 세션 수량 동기화, 결제 직전 합계 및 기존 예매 조회를 live smoke로 확인한다. 실제 결제·환불은 별도 승인된 금액과 수단으로만 검증한다.

애드온 주문이 생긴 뒤에는 애드온을 모르는 이전 API로 단순 rollback하지 않는다. 신규 판매를 `active=false`로 중단하고 기존 주문의 승인·취소·특전 처리 코드를 유지한 채 수정한다. DB migration과 주문·선점·특전 기록은 되돌리거나 삭제하지 않는다.

검증 범위: 실 PostgreSQL 동시 선점, 주문 준비/복구, 동기 승인, 비동기 DONE/replay, 지연 승인 재고 충돌, 좌석/전체 취소, 거절 후 특전 복구, 특전 CSV와 재무 원장. 로컬 브라우저 검증은 PG 결제가 없는 fixture로 수행한다. 실제 운영 트래픽의 지연과 실결제 성공은 별도 증거가 필요하다.
