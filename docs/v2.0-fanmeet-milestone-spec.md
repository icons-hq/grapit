## Context — 왜 이 milestone이 필요한가

`heygrabit.com`은 v1.1을 Phase 21에서 닫고 안정화·고도화된 한국 단일 시장 MVP 상태로 v2.0에 진입한다. **걸룰스(Girl Rules) 팬미팅 — Grabit 첫 실전 이벤트 — 은 이 플랫폼이 처음으로 다음 6개 차원에서 동시에 검증되는 자리다.**

1. 글로벌 트래픽 흡수 (좌석 2,000석 / 동접 1만~2만, GMMTV 태국 + iQIYI 글로벌 팬덤)
2. 5개국 언어 (한·영·태·중간·중번)
3. 4종 결제 (Toss·Alipay+·truemoney·해외카드)
4. 다국적 컴플라이언스 (한국 PIPA·태국 PDPA·중국 PIPL + 국외이전 동의)
5. 운영팀 콘솔 풀 워크플로 (이벤트 등록·Q&A·CS·QR·audit log)
6. 트래픽 폭주 이벤트 운영 (대기열·prewarm·on-call)

이 milestone이 깨지면 Grabit 자체의 신뢰 손상이 GMMTV·아티스트·글로벌 팬덤에 직격탄. 단일 이벤트 PR 사고가 플랫폼 사업 손상으로 이어진다.

### 마스터 일정 (KST) — 정합성 수정본

```
오늘 4/29 ─────── 5/15 ─────── 5/말(5/27~31) ─────── 7/4 ──── 7/10
   D-0           D-16              D-28~32           D-66    D-72

[v2.0 시작]   [M1: 광고/가입]   [M2: 부하+결제 cutover+티켓팅]   [M3: 행사]   [M4: 회고]
```

**핵심 정합성 원칙:** 부하 PASS · DR 훈련 · on-call 플레이북 · QR 발급 코드는 **5/말 결제 cutover 이전 게이트**다. 1~2만 동접 흡수 검증 안 된 상태로 실 트래픽 받으면 사고. 5/15 ~ 5/말 사이 7~10일을 **production-ready 가속 구간**으로 운영.

| 시점 | 이벤트 | 결제 상태 | 게이트 |
|---|---|---|---|
| 5/15 | 사이트 광고 오픈, 회원가입 유도 | 결제 버튼 disabled (`BOOKING_ENABLED=false`) | M1 통합 테스트 PASS |
| 5/22~26 | 부하·DR·on-call·QR 발급 코드 검증 (5/말 cutover 직전) | 여전히 disabled | k6 1~2만 PASS, DR 훈련 PASS |

| 7/4 | 팬미팅 행사 | (티켓팅 마감) | QR 검증·현장 운영 콘솔 PASS |
| 7/10 | 정산·회고 | — | 입장 데이터 export 완료 |

## Milestone Goal

**2026-07-04 걸룰스 팬미팅을 무사 진행하기 위해, heygrabit.com 위에 1~2만 동접 흡수 가능한 5개국 다국어 + 4종 결제 + 운영팀 풀 콘솔을 구축하여, 5/15 광고 오픈 → 5/말 부하 PASS 후 결제 cutover · 티켓팅 오픈 → 7/4 행사 종료까지 단일 critical incident 0건으로 운영한다.**

## Sub-projects (6개로 분해)

각 sub-project는 GSD가 phase 분해 시 카테고리 묶음으로 사용. GSD가 자동으로 phase별 순차 진행.

```
                      ┌─ SP-1 i18n 인프라 ─┐
SP-0 prod 호환 ───────┤                    ├──→ SP-2 Auth/컴플라이언스
   (3일)              │                    ├──→ SP-4 Booking/Payment + QR 발급 (테스트키)
                      └────────────────────┴──→ SP-5 운영팀 콘솔 + QR 검증 (행사)
                                            └──→ SP-3 트래픽 + 부하·DR·on-call (Independent)
```

### SP-0 : 기존 prod 호환 + Feature Flag (가장 먼저, 3일)
**책임**: 다른 모든 sub-project를 unblock
**산출물**:
- DB 마이그레이션 expand 단계 (신규 테이블·컬럼 ADD only, nullable + default, 한국어 데이터 ko 컬럼 복제)
- Feature Flag 헬퍼 (`libs/shared/src/flags.ts`): `bookingEnabled`, `lineLogin`, `langTH`, `langZHCN`, `langZHTW`
- i18n URL 정책 결정 적용 (next-intl `localePrefix: 'as-needed'`, `defaultLocale: 'ko'`)
- Cloud Run canary deploy 정책 (5%→50%→100%, revision tag)
- `min-instances` 환경변수 정책 (M1: min=2, max=20 / M2 prewarm: 100~200)
- `.planning/milestones/v2.0-fanmeet/` 디렉토리 생성

### SP-1 : 글로벌화 — i18n + 다국어 콘텐츠 파이프라인 (5~7일)
**책임**: 5개 언어 동등 노출 + AI 번역 워커 + 법적 고지 한·영 수동 락
**산출물**:
- next-intl 설정 (locales=[ko,en,th,zh-CN,zh-TW], prefix as-needed)
- 사용자 언어 감지 (Accept-Language + GeoIP) → 한국 외 사용자에게 토스트 "View in English?" (자동 redirect 안 함, SEO 영향 0)
- 계정 언어 설정 (DB users.preferred_locale 컬럼)
- 자동 번역 파이프라인:
  - 운영팀 한국어 입력 → AI 에이전트 (DeepL API + LLM 후처리) → 4개 언어 생성 → 운영팀 검수 큐
  - "자동 번역됨" 라벨 강제 노출 (분쟁 방지)
  - 원문 수정 시 5개 언어 재생성 트리거
- 법적 고지 schema-locked 한·영 수동 입력 필드 (자동 번역 차단):
  - 유의사항·취소환불 정책·예매 안내 모달
  - 태국·중국 사용자는 영어 버전으로 확인
- 이메일·SMS 다국어 템플릿 (Resend·Infobip)
- 시간대 표시 (KST/ICT/CST를 사용자 로케일에 맞춰 + KST 명시)
- 통화 표시 (KRW + 추정 환산가 + disclaimer)
- hreflang + 다국어 sitemap.xml

### SP-2 : 회원·인증·컴플라이언스 (5~7일)
**책임**: Line 로그인 + 5개국 SMS + 다국적 동의
**산출물**:
- Line 로그인 (passport-line, OAuth 4종에서 5종으로 확장)
- 이메일 인증 30분 만료 + 즉시 재요청 버튼
- SMS OTP 5개국 번호 수신 검증 (Infobip 해외번호 비용 사전 검증)
- 3대 동시접속 제한 (refresh token family)
- 다국적 동의 체계:
  - 한국 PIPA 필수/선택 항목 (전자상거래법·정통망법 표준 템플릿)
  - 국외이전 동의 (GMMTV·iQIYI에 데이터 공유)
  - 태국 PDPA 영문 안내문
  - 중국 PIPL 영문 안내문 (중국 본토 팬 영어로 안내)
  - 14세 미만 차단 또는 법정대리인 동의
  - EU 사용자 안내 (영문 일반 안내문, 검토 없음)
- 동의 audit log: 날짜·버전·언어·IP·동의 항목별 기록
- footer 표기: 사업자정보·통신판매업 신고번호·환불계좌·DPO 연락처
- 약관 변경 30일 공지 (한국법) + 마케팅 옵트아웃 1-click

### SP-3 : 트래픽 흡수 + 부하·DR·on-call (5/말 cutover **이전** 완료, 7~10일)
**책임**: 1~2만 동접 흡수 + 봇 차단 + prewarm + 부하 PASS 게이트
**산출물 (M1 광고 오픈 5/15 까지)**:
- 대기열 시스템:
  - Valkey Sorted Set (score = epoch_ms + jitter)
  - Batch admission (5초마다 N명 풀어주기, N은 대기열 길이 함수)
  - 본인 순번 SSE/WebSocket 스트리밍 (예상 대기 시간 + 잔여 좌석 수)
  - 한 계정 3대 동시 접속 제한 (refresh token family와 동일 정책)
- Cloud Run prewarm 자동화:
  - Cloud Scheduler가 오픈 30분 전 `min-instances=100~200` 자동 상향
  - 직후 점진 하향 (timer 또는 traffic-driven)
- Cloudflare WAF 룰 베이스:
  - per-endpoint rate limit (login·register·SMS·booking)
  - 봇 점수 기반 challenge (CAPTCHA 없이 통과 / 차단 분기)
  - 매크로 패턴 차단

**산출물 (5/말 cutover 이전 게이트, 5/22~26)**:
- **부하 테스트 (k6)**:
  - 1만 동접 baseline 시나리오 PASS (p95 < 2초, 에러율 < 1%)
  - 2만 동접 stress 시나리오 PASS
  - 좌석 매진 워스트 케이스 (전 좌석 락 → 결제 → 환불 cycle)
- **DR 훈련**:
  - DB 복원 (PITR 7일 내 임의 시점)
  - Valkey 페일오버
  - Cloud Run 롤백 시나리오
- **인프라 보강**:
  - pgBouncer transaction pooling
  - Cloud SQL HA + read replica
  - Cloud Run 인스턴스당 풀 사이즈 조정
- **on-call 플레이북**:
  - PG 장애 / Valkey 장애 / DB 장애 / CDN 장애 분기
  - Sentry 알람 룰 (에러율·latency·결제 실패율)
  - 연락 트리 (운영자·기술자·외부 PG 담당자)
- **부정구매 차단** (M2 결제 활성 시 활성):
  - 카드 BIN 검증 (BIN별 국가/카드사 매칭)
  - 디바이스 핑거프린트 (FingerprintJS Pro 또는 자체)
  - 동일 번호·이메일·카드 매크로 패턴 score

**게이트 통과 조건 (cutover 직전)**: 부하 + DR + on-call PASS. 한 줄이라도 FAIL이면 cutover 연기.

### SP-4 : 좌석·예매·결제 정교화 + QR 발급 (7~10일)
**책임**: Toss 테스트키 기반 결제 풀 흐름 (5/말 cutover = 토글 1개) + 예매 완료 시 QR JWT 발급
**산출물**:
- 다층 SVG (1/2/3층) 업로드·렌더링·전환 UI
- 좌석 락 메커니즘 (이미 v1.0에 베이스 존재, 다층·다국어로 확장)
- 결제 7분 카운트다운 (2분 잔여 시 빨간색)
- 결제 화면 + 결제수단 4종 통합 (Toss SDK):
  - 국내 카드/간편결제
  - 해외카드 (Visa·Master·UnionPay) + 환차손 disclaimer + 동의 체크박스
  - Alipay+
  - truemoney wallet
- 마지막 사용 결제수단 자동 선택
- 결제 실패·시간 초과 시 좌석 자동 복귀
- 단계별 취소 수수료 엔진:
  - 예매 당일 자정 이전: 0%
  - 8일 전 이전: 10%
  - 7~3일 전: 30%
  - 2~1일 전: 50%
  - 당일 이후: 환불 불가
  - 이벤트별 설정 가능
- 환불 흐름:
  - 환불 내역 미리 확인 화면 ("한 번 확인하면 되돌릴 수 없음")
  - Toss 환불 자동 전송
  - 환불 진행 상태 머신: 요청 → PG 전송 → PG 처리 → 환불 완료
  - 예상 입금일 표시 (영업일 3~5일 / 5~10일 / 5~10일 결제수단별)
  - 입금 지연 시 마이페이지 CS 문의 버튼 자동 표시
- 취소 후 랜덤 홀딩 1~10분:
  - pg-boss 지연 job + uniform random jitter
  - 운영팀 "즉시 개방" 수동 조작 가능
- 좌석 변경 정책: M2 cut 안에서 결정 (변경 가능 / 불가 / 동일 등급만 등)
- 1인 N매 정책 엔진: 이벤트별 설정 (기본 1매), 계정·실명·번호·카드 매크로 회피 룰
- **QR 발급 코드 (예매 완료 시점)**:
  - JWT + HMAC payload (위변조 방지)
  - 행사 D-day 24시간 전 이메일 발송 트리거
  - JWT secret rotation 정책 (행사 당일 전용 키)

### SP-5 : 운영팀 콘솔 + 행사 운영 (7~10일 + 행사 운영 5~7일)
**책임**: 이벤트 등록·Q&A·CS·배너·audit (M1) + QR 검증·현장 운영 (M3 행사 직전)
**산출물 (M1, 5/15 까지)**:
- 이벤트 등록 콘솔:
  - 5탭 다국어 입력 (이벤트명·소개·공연장명·교통)
  - 출연자 카드 (출연자/작가/캐릭터, 이름·캐릭터명·SNS·프로필 이미지)
  - 멀티 SVG 업로드 (1/2/3층)
  - 가격 단계 (등급·가격·수량·색상 코드 매핑)

## Success Criteria

## Architectural Decisions (확정)

| 영역 | 결정 |
|---|---|
| i18n | next-intl, `localePrefix: 'as-needed'`, `defaultLocale: 'ko'`, locales=[ko,en,th,zh-CN,zh-TW] |

| 대기열 | Valkey Sorted Set + batch admission + SSE 진행 노출. CAPTCHA 없음 |
| WebSocket | Socket.IO + ioredis Redis adapter (Phase 7에서 구축됨) |
| Cloud Run | min=2/max=20 (M1) → prewarm 100~200 (M2 cutover 직전 30분, Cloud Scheduler) |
| WAF | Cloudflare per-endpoint rate limit + 봇 점수 + 매크로 패턴 차단 |
| 다국어 콘텐츠 | 운영팀 한국어 입력 → AI 에이전트 (DeepL + LLM 후처리) → 검수 큐 |
| 법적 고지 | 한·영 수동 입력 schema-locked, 자동 번역 차단. 태/중 사용자는 영어로 확인 |
| 시간대 | KST/ICT/CST 사용자 로케일에 맞춰 표시 + KST 명시 |
| 통화 | KRW + 추정 환산가 disclaimer |
| QR | JWT + HMAC payload, 오프라인 fallback DB sync, 행사 당일 전용 키 회전 |
| 부정 구매 차단 | BIN 검증 + 디바이스 핑거프린트 + 매크로 score (CAPTCHA 없음) |

   ```bash
   cp docs/v2.0-fanmeet-milestone-spec.md .planning/MILESTONE-CONTEXT.md
   ```

   ```bash
   git worktree add ../grapit-v2.0 -b v2.0/fanmeet-launch main
   cd ../grapit-v2.0
   ```
   격리 안 해도 GSD는 main에서 v2.0/* feature 브랜치를 자체 관리.
