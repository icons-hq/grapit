## 발견과 수정

- 현장 모니터가 미선택/미조회에도 정상이라고 표시하는 오류를 실제 화면과 RED 테스트로 재현. 조회 전·연결 대기·실패를 구분하고 경고 없음을 관측 범위로 제한했다. 영문 내부 KPI/동기화 상태를 업무 문구로 바꾸고 요약과 로그 필터 범위를 설명한다.
- 현장 로그가 일반 감사 권한을 요구해 scanner가 403으로 막히는 문제를 HTTP/실DB RED로 재현. 요약/화면과 같은 `field.scan.verify`로 맞추고 일반 재무 계정은 차단한다. raw QR와 구매자 연락처는 내보내지 않는다.
- 현장 로그의 날짜 범위가 UTC였으나 화면은 KST였던 경계를 실제 HTTP/DB RED로 재현. KST 날짜 시작/끝으로 수정했다.

## 현재 검증

- 현장 HTTP/PostgreSQL 26/26, 관련 UI 5/5 및 기존 monitor service 4/4 통과. 새 로그 응답에 예매번호·좌석·담당자 이름·온라인/오프라인 출처를 제공해 빈 예매번호/원시 담당자 ID/미확인 온라인 표기를 보완했다. 추가 상태·언어·접근성 검증과 최종 리뷰는 진행 중이다.
- 격리 migration 리허설 1/1 통과: 개편 전 `0033`까지 적용한 빈 PostgreSQL에 계정/소셜연결/선택동의/부분취소 원금/입장한 활성 QR/취소 QR/활성·지급 특전/과거 지급·입장 기록을 준비하고 `0034`–`0037` 적용. 13개 테이블의 모든 기존 열·행·식별자가 동일했으며 KRW 104,000원/USD 8,000 minor units, 활성 QR 1장, 지급 특전 1개를 보존했다. 재실행도 원장을 바꾸지 않았다. 운영 DB 복제나 운영 migration은 아니다.
- API unit 1,259 / Web unit 773 / shared unit 148, PostgreSQL 거래 회귀 65, 현장 HTTP 회귀 26, migration 보존 리허설 1을 통과했다. 최종 작은 문구/접근성 변경의 관련 UI 12개도 통과했다. API/Web/shared typecheck와 Web production build 성공. 변경 파일 lint 오류 0개이며 기존 React 경고 6개와 integration 파일 lint 제외 3개는 남아 있다.
- 원 증거는 로컬 `grapit-revamp-autonomy-2026-09-21/browser/77`–`110`, `tests/`, `integrated-buyer-final.json`이다. 고객/인증/QR 원문은 공개 산출물에 포함하지 않는다.

## 통합 고객 여정에서 발견한 추가 문제와 수정

- 해외 지갑/상세가 원문 제목만 반환했다. 소유권 확인 뒤 현재 원문과 hash가 일치하는 published 번역만 목록·상세·주문 복구에 적용하고, 사용자와 언어별로 query cache를 분리했다. 검수 중/오래된 번역은 원문으로 돌아간다.
- 원장의 KRW 금액을 결제수단의 청구 통화로 해석해 USD 카드가 국내 카드로 보였다. 주문 원금은 유지하고 실제 PG 청구 통화로 결제수단을 식별한다.
- 일부 지갑·취소 마감·메일 예정/환불 이력이 브라우저 시간대를 사용했다. KST로 고정·명시했다. 브라우저를 America/New_York로 바꿔 19:00 KST가 유지되는 것을 확인하고 원래 시간대로 복원했다.
- 태국어/중국어 결제 완료·QR·오류 문구의 영문 누락, 좌석 선택의 한국어 고정 달력/회차/층/금액/타이머/버튼을 번역 계약으로 옮겼다. 공개 API의 한국어 오류 원문은 진단용으로 보존하고 외국어 전역 알림은 현재 UI 언어로 표시한다. 법적 원문과 실제 동의 문서 버전·언어는 바꾸지 않는다.
- 좌석도 클릭 외에 네이티브 목록 선택을 추가했다. 같은 좌석 식별자·선택 callback을 사용하고 판매/잠금/제외/매수 한도를 유지한다. 키보드 Tab→Enter→목록 화살표→선택 버튼 Enter로 실서버 잠금과 KRW 52,000 요약·결제 확인 진입을 수행했다.
- 성공한 취소 직후 열려 있던 취소 견적이 재조회되어 400 알림을 띄웠다. 견적은 다음 열기용 stale로만 표시하고 예매 기록을 갱신한다. 처리 중/이미 취소한 좌석의 견적 자동 조회도 막는다.
- 취소된 주문의 과거 결제 복귀 주소가 결제 실패로 표현됐다. 취소/환불 상태와 내 예매 확인으로 안내하고 새 결제를 호출하지 않는다. 티켓의 상태 필드 이름도 취소 항목에서 ‘유효’로 오해하지 않도록 바꿨다.

합성 일반 구매자의 원 주문 KRW 104,000 / PG USD 80.00을 한 좌석 USD 40.00 취소 후 나머지 USD 40.00 전체 취소로 확인했다. 첫 취소 뒤 두 번째 QR·특전은 유효했고, 전체 취소 뒤 Ticket Item 2개 cancelled / QR 2개 revoked / 특전 2개 inactive였다. 원 주문·Payment 금액은 104,000, PG 원 승인 minor amount는 8,000으로 유지됐다. 선호 언어 저장 뒤 국가 TH와 마케팅 미동의도 유지됐다. 이번 주문의 공급자 응답은 명명된 **격리 로컬 simulator**이며 실제 해외 카드 승인을 의미하지 않는다. 실제 Toss test 왕복 증거는 #224를 따른다.

## 시각·접근성 근거

- 1280px 데스크톱, 390px 구매·티켓, 320px 현장·운영 목록에서 실제 렌더와 가로 넘침을 확인했다. 640px 지원 화면에 CDP의 page scale 2를 적용해 확대·이동 가능한 본문을 확인했다. 이는 데스크톱 브라우저 메뉴의 200% zoom이나 실제 휴대폰을 대신한 인증은 아니다. 테스트 후 크기·확대·시간대 override를 복원했다.
- 지갑은 키보드만으로 필터→예매 링크→Enter 상세 진입을 확인했다. 좌석 선택 목록은 실제 잠금까지 확인했다. 모달 닫기와 판매 상태 접근성 이름도 네 언어로 제공한다.
- `concepts/buyer-home-v1.png`, `buyer-checkout-v2.png`, `admin-preparation-v1.png`, `field-mobile-states-v1.png`와의 주요 차이는 개별 validation 문서의 비교표를 따른다. 이번 통합 수정은 기존 흰색·보라색 체계를 유지하며, 실제 좌석도와 PG 위젯을 쓰고 목록 선택을 보조 수단으로 추가했다. 티켓 상세는 긴 공연 제목을 여러 줄로, 모바일 결제 영역은 한 열로 유지한다.
- 실제 미선택·빈 결과·고객/재무 권한 거부·취소 QR 비노출·대기열 재시도/만료 후 재입장·연결 대기 근거가 있다. admin cutover는 외부 gate가 열려 있음을 그대로 표시한다.

## 리뷰와 출시 후보

고정 구현 snapshot `fe5ab738882a4ffdd8a038030bb336d54b75de1f`의 Standards/Spec 병렬 검토는 각각 0건이다. 이후에는 실행한 근거와 운영 문서를 갱신했다. PR CI의 최종 commit을 출시 후보 증거로 고정한다. 실기기·실물·실입금·오픈 결정은 #214/#223의 별도 gate다.

첫 PR CI에서 기존 E2E의 고정 URL stub이 새 `locale` query를 받지 못하고, 좌석도의 잘못된 grid role을 가정하던 locator가 실패했다. query를 포함한 동일 예매 경로를 fixture로 받도록 하고 실제 canvas 식별자로 click geometry 검증을 유지했다. 한국어 결제 실패의 기존 상세 사유도 유지하며, 취소 상태 안내는 분리했다. 수정 commit의 CI로 최종 판정한다.
