# 탐색·가입·계정 개편 검증

구현 과제: [#217](https://github.com/icons-hq/grapit/issues/217). 결제 복구 변경 이후의 별도 구현 단위다. 격리된 로컬 PostgreSQL/Valkey와 합성 일반 고객 계정으로 확인했으며 운영 회원·동의·결제 데이터는 수정하지 않았다.

## 구현한 흐름

- 홈에서 공연 검색, 판매 중/오픈 예정/지난 공연 필터, 실제 공연 기간·KST·시작 가격·수수료 별도 표시, 내 티켓과 이용 안내 진입을 제공한다. 필터는 서버에서 count와 pagination 전에 적용한다. 검색/홈/장르 목록은 같은 현재 판매 상태와 가격 projection을 사용한다.
- 배너는 운영 등록 자료를 유지하고 수동 이전/다음 조작을 제공한다. 작은 화면에서 원본 문자가 잘리지 않도록 전체 이미지를 표시한다. 포스터 없는 실제 공연은 아이콘 대체물을 사용한다.
- 로그인, 이메일 인증·재요청, 비밀번호 재설정과 소셜 가입 완료에서 선택 언어와 같은 사이트의 안전한 `returnTo`를 보존한다. 외부 주소·인증 화면 순환·제어 문자·중첩 인코딩 경로·인증 비밀을 포함한 복귀 주소는 거부한다.
- 인증이 미완료된 회원도 탐색/도움말을 이용한다. 예매 진입에서 이메일 또는 휴대폰 인증으로 안내하고 완료 후 같은 공연으로 복귀한다. 서버의 기존 인증·소유권 검사는 유지한다.
- 앱 초기화의 refresh rotation은 동시에 한 번만 실행한다. 회원을 바꿀 때 예매 목록/상세 캐시를 사용자별로 분리하고 이전 사용자의 placeholder 데이터를 재사용하지 않는다.
- 계정 탭·로그아웃·설정에서 URL 언어를 유지한다. 국가와 UI 언어는 별개이며 신규 이메일/소셜 가입은 선택한 UI 언어를 선호 언어로 저장한다. 기존 미인증 번호도 증명 후 저장할 수 있고, 인증된 번호의 변경 시작/취소 조작을 제공한다.
- 이메일 발송 공급자가 실패하거나 예외를 반환해도 이미 생성된 계정을 다시 만들게 하지 않는다. 가입 결과에 `emailDeliveryFailed`를 추가하고 인증 화면에서 발송 재시도를 안내한다. 요청/재전송도 성공으로 잘못 표시하지 않는다. 비밀번호 재설정의 계정 열거 방지 응답은 유지한다.
- 도움말의 로딩/조회 실패/빈 공지를 구분하고 실제 문의·약관·개인정보 경로를 제공한다.

## 실제 브라우저 증거

2026-09-21 Chrome 및 앱 내 브라우저에서 1440×1000, 390×844로 조작했다.

1. 영문 홈 → Girl Rules 검색 → 단일 결과 → 공연 상세를 확인했다. 지난 공연 필터는 종료 공연만, 오픈 예정 필터는 실제 빈 상태를 보였다.
2. 기존 일반 회원의 내 티켓 → 계정 → 설정이 영문을 유지했다. 계정 국가는 Singapore, 가입 기간은 실제 값으로 표시됐다. 전화번호 변경을 시작하면 입력이 열리고 취소하면 이전 검증 상태로 돌아왔다.
3. 신규 합성 태국 구매자의 비로그인 예매 → 태국어 로그인 → 이메일 인증 → 오답 안내 → 정상 코드 → 원래 `/th/booking/...` 복귀를 확인했다. 미인증 상태에서 도움말에 머무를 수 있었다.
4. Mai 계정에서 이전 Lin 계정의 예매가 노출되지 않았고 실제 예매 수는 0이었다. DB readback에서 이메일 인증 true, 인증 코드 consumed 1개를 확인했다. 코드 자체는 테스트 fixture로 준비했으며 외부 메일 도달을 검증한 것은 아니다.
5. Thai → Simplified Chinese 언어 메뉴 조작 후 국가 TH와 마케팅 미동의는 유지됐고 preferredLocale만 zh-CN으로 저장됐다. 설정·홈·지원·법적 문서 경로도 선택 언어를 유지했다.
6. 중국어 약관 페이지에서 한국어가 나오던 결함을 재현하고 수정했다. 기존 영문 원문과 중국어 fallback 안내를 실제 새로고침 후 확인했다.

## 법적 문서 언어 수정

법적 페이지의 `force-static`은 proxy가 전달한 locale header를 비워 모든 언어에서 한국어를 선택하게 했다. request locale을 읽도록 해당 세 경로를 dynamic으로 변경했다. [Next.js 공식 설명](https://nextjs.org/docs/15/app/api-reference/file-conventions/route-segment-config#dynamic)과 현재 런타임 재현을 함께 근거로 삼았다. 원문 약관/개인정보/마케팅 내용과 기존 동의 기록은 바꾸지 않았다.

가입 동의 팝업도 KO에서는 기존 한국어, EN/TH/ZH에서는 기존 영문 문서를 사용한다. TH/ZH에는 기존 fallback 안내를 표시한다. 새 동의 기록의 language는 실제 문서인 ko/en이며, 다른 문서 언어나 버전의 이전 선택을 그대로 재사용하지 않는다.

## 검증 및 남은 경계

- Web unit 739개, API unit 1,322개, Shared unit 148개 통과. 법적 언어 변경의 추가 회귀 21개 포함. 실제 PostgreSQL 통합 28개 통과.
- API/Web TypeScript 및 production build 통과. 가입 시 국가와 독립적으로 선호 언어를 저장하는 추가 수정은 API 관련 113개 테스트로 검증했다.
- API/Web lint 오류 0개. API 통합 test 경로는 기존 ESLint 설정의 검사 대상 밖이며, Vitest/TypeScript로 검증했다.
- 외부 SMS·메일 도달·소셜 공급자 로그인과 실기기 검증은 #214에 남는다. synthetic code와 데스크톱 viewport를 외부 도달/물리 기기 증거로 바꾸어 말하지 않는다.
- 좌석 달력 등 기존 화면에 남은 한국어/영문 고정 문구, 티켓 상태·부분취소, 운영/현장/정산 개편은 #218–#223의 후속 범위다.
- Chrome 확장 팝업 조작 중 Mac이 재잠금되어 새 PG 리허설 추가 실행은 중단됐다. 앱 내 브라우저의 실제 계정/탐색 검증은 계속 수행했다.
