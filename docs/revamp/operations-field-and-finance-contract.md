# 운영·현장·정산 계약

2026-09-21 사용자 자율 위임에 따른 선택. 기존 거래와 고객 권리는 보존한다. 인터뷰·현장 리허설의 결과로 가장하지 않는다.

## 공연 준비와 판매

공연을 선택한 맥락에서 `기본 정보 → 회차·좌석·가격 → 언어·특전 → 검수 → 공개·판매`로 진행한다. 기존 편집 API를 유지하고 초안 저장·재개를 지원한다. 화면의 단계 이동과 저장을 혼동하지 않게 표시한다. 공연 게시, 예매 가능 기능 플래그, 실제 판매 시작 시각은 서로 다른 조건이다.

공연·회차 selector는 제목·KST 일시·상태로 선택하고, URL의 선택 맥락을 예매/좌석 운영/현장/정산으로 전달한다. 실제 UUID는 진단 상세에서 복사 가능하지만 정상 업무의 필수 입력으로 요구하지 않는다.

검수 결과는 오류가 있는 단계로 연결한다. 가격/좌석/회차/정책 변경은 기존 판매된 좌석·결제 snapshot을 덮어쓰지 않는다. 판매 중 변경은 영향 미리보기와 기존 API 제한을 따르며 공개 직전 확인에는 대상 공연·회차·일정·결제수단·준비 누락을 표시한다. 미리보기는 실제 공개가 아니다.

특전 identity는 시스템이 생성·보존하고 운영자는 이름·내용·제공 조건을 편집한다. 포함 특전, 한정 배정, 테스트 배정, 실제 반영, 결과 고정을 구분한다. 테스트 배정은 고객 권리에 부착하지 않는다. 이미 지급된 권리를 배정 재실행이나 rollback으로 삭제하지 않는다.

## 역할과 고객 대응

| 역할 | 주요 업무 | 제한 |
| --- | --- | --- |
| 운영 | 공연·판매·예매 확인, 허용된 CS 조치 | 재무·권한 부여를 묵시적으로 포함하지 않음 |
| 검수/승인 | 번역·공개 준비 검수와 승인 | 기존 capability 범위 안에서만 변경 |
| 재무 | 매출·취소·PG 대조·정산/export | 현장 지급이나 계정 최고권한과 분리 |
| 현장 | 지정 회차의 검표·허용된 특전 지급 | 다른 회차/결제/회원 관리에 접근 불가 |
| 관리자 | 필요한 capability 배정·감사·예외 처리 | 중요한 조치는 사유·대상·전후 상태 기록 |

1인 운영자는 역할을 겸임할 수 있으나 API capability 검증은 유지한다. UI에서 메뉴를 숨기는 것만으로 접근 제어를 대체하지 않는다.

고객 대응은 예약번호/공연/상태/구매자 검색에서 같은 예매 상세를 연다. 원 주문·PG 확인 시각·좌석별 권리·취소 요청/완료·이메일 전달 이력을 구분한다. 재발송·취소·좌석 재오픈·수동 대조 같은 조치는 실제 대상과 결과를 보여주고 감사 기록을 남긴다. 조회 실패를 정상/0건으로 요약하지 않는다. DB 직접 수정은 일상 업무 경로로 제공하지 않는다.

## 현장 입장과 특전

- 새 기본 계약은 **한 QR → 한 Ticket Item의 입장**이다. 같은 구매자의 다른 좌석은 자동 처리하지 않는다. 현재 구현의 계정·회차 일괄 처리를 변경하는 결정이며 기존에 기록된 입장 결과는 변경하지 않는다.
- 동행자는 각 좌석 QR로 따로 입장한다. 화면에서 좌석·회차·유효성·이전 입장 시각을 확인한다. 이미 처리한 QR은 중복으로 표시하고 집계를 늘리지 않는다. QR은 입장 뒤에도 구매자가 열 수 있다.
- 별도 일괄 입장이 필요하면 구체적으로 선택한 유효 좌석만 확인 후 처리한다. 이번 기본 화면에 자동 전원 입장 기능을 남기지 않는다.
- 입장 처리와 특전 품목 지급은 별도 버튼·권한·원장이다. 입장했다고 특전을 지급 완료로 바꾸지 않는다. 품목·좌석·미수령 상태를 확인하고 지급을 확정한다. 중복 요청은 기존 지급 결과를 반환한다.
- 검표 카메라 실패에는 QR 입력/허용된 좌석·예약 검색 경로를 제공한다. QR credential을 임의 생성하거나 결제 확인을 건너뛰지 않는다.
- 네트워크 단절 시 기존 offline 입장 queue는 '동기화 대기'로 표시한다. 서버 확정 집계와 섞지 않는다. 재연결 시 중복/취소/다른 단말 처리 충돌을 보여주고 완료로 일괄 덮어쓰지 않는다.
- 실물 특전의 offline 지급 확정은 지원하지 않는다. 연결 복구 또는 책임자 예외 원장 절차가 필요하다. 앱 검증과 실물 인수·재고 확인은 별도 gate다.
- 재입장 허용·양도는 자동화하지 않는다. 권한 있는 책임자의 기존 예외 절차와 이력을 따른다.

현장 검증은 동행자 분리 도착, 2대 동시 스캔, 중복, 다른 회차, 취소 대기/완료, 입장 후 QR 조회, 부분취소 잔여 티켓, 품목별 중복 지급, offline→재연결 충돌을 포함한다. 실제 카메라·회선·실물 지급 리허설은 별도 실행 증거를 요구한다.

## 지표 사전와 정산

| 지표 | 의미 | 금지하는 혼동 |
| --- | --- | --- |
| 원 주문액 | 구매 당시 티켓·서비스 수수료 합계 KRW snapshot | 취소 후 잔여액으로 덮어쓰기 |
| 확정 결제액 | 공급자 승인 확인된 원 결제의 합계 | 미결제 예매 합산 |
| 취소/환불액 | 확정된 취소 금액, 처리 중은 별도 | 요청액을 완료 환불에 합산 |
| 잔여 티켓 금액 | 아직 유효한 Ticket Item의 금액 | 원 매출 또는 PG 잔액과 동일시 |
| 취소·서비스 수수료 | 구매 정책으로 남긴 금액 | PG 수수료와 합치기 |
| 공급자 청구·취소 | 실제 PG 통화와 minor-unit 금액 | KRW와 USD를 단순 합계 |
| PG 정산 예정/완료 | 공급자 정산 자료의 지급 기준 금액·일자 | 승인일 기준 매출과 같은 일자로 취급 |
| 은행 실입금 | 증빙으로 확인된 실제 수령액·일자 | PG 완료만으로 입금 확정 |

화면과 export에 공연/회차, 기간 기준(승인일·취소일·지급일), KST, 통화, 조회 시각과 범위를 표시한다. 결제되지 않은 상태·조회 전·조회 실패·성공한 0건을 구분한다. 원본 식별자와 누적 취소 이력을 대조 가능하게 보존한다. 외화는 별도 열과 통화별 소계로 보고하며 환산값은 기준 환율/시각이 있는 보조 수치다.

마감 순서는 원장 집계 → 공급자 자료 대조 → 은행 증빙 대조 → 차이 원인/미해결 기록 → 권한 있는 담당자 확정이다. 단순 화면 조회를 회계 마감으로 표시하지 않는다. 현재 기능에 실입금 증빙/마감 기능이 없으면 미확인으로 유지하고 PG 정산 완료 표시로 대체하지 않는다. 재개방은 원본을 지우지 않고 변경 사유와 후속 대조를 남긴다.

표본 검증에는 승인과 취소 날짜가 다른 주문, 2석 중 1석 취소, 마지막 좌석 수수료, USD 청구·부분취소, PG 처리 중, 원화/외화 CSV 대조를 포함한다. 공급자 정산/실입금 수치가 확보되지 않은 표본은 외부 검증 미완료로 남긴다.
