# 관리자 화면 점검과 개편

2026-09-22. Grabit 기준 커밋 `2875efef`, 참고 icons-ip `f73fab58`. 사용자 요청에 따라 icons-ip의 최근 운영 화면을 실제로 확인하고 티켓 예매 업무에 맞게 재해석했다. 아래 내용은 구현·로컬 검증 단계의 기록이며, 이 단계에서는 운영 환경과 데이터를 변경하지 않았다.

## 판단

핵심 문제는 기능 수 자체보다 정보의 우선순위, 중복 진입점, 기술 용어, 선택한 업무 대상의 불명확함이었다. 실제 화면에서 대시보드의 PR·테스트 기록이 업무보다 먼저 나오고, 공연 목록에는 목록을 필터링하지 않는 별도 공연 선택창이 있었다. 판매 시작 점검에는 실행 핸들러가 없는 활성화 버튼도 있었다.

공연 준비, 예매·취소, 좌석 복구, 특전, 입장, 정산은 티켓팅에 필요한 기능이므로 유지했다. icons-ip의 상품 재고·택배·교환·배송 기능은 가져오지 않았다. 흰 업무 패널, 옅은 회색 배경, 업무별 메뉴 묶음, 검색, 단계별 정보 표시를 가져오되 Grabit의 보라색 선택 표시는 유지했다. 메뉴 수가 다른 두 제품에 동일한 즐겨찾기 시스템을 추가하지 않았다.

## 동작과 안전 경계

- 메뉴·현재 위치·화면 접근 제한이 같은 경로/권한 정의를 사용한다. 화면에서 메뉴를 숨기는 것과 서버의 기존 권한 검사는 별개이며 둘 다 유지한다. 일반 관리자 권한을 다른 역할에 자동 부여하지 않는다.
- 과거 메뉴 이름으로도 검색할 수 있다. 모바일 메뉴는 이동 후 닫히고 다른 페이지로 이동하면 본문 처음으로 돌아간다. 현재 메뉴에는 `aria-current`를 표시한다.
- 관련 업무 사이에서는 공연·회차 선택을 유지하고, 공연 목록/보안/회원 등의 무관한 화면에는 선택값을 붙이지 않는다. 공연·회차 변경 시 이전 예매 선택값을 제거한다.
- 예매 표는 공연·좌석·금액·상태를 우선한다. 결제사 주문번호와 실패 진단 코드는 예매 상세에서 계속 확인할 수 있다. 판매 좌석은 `석`, 예매는 `건`으로 표시한다.
- 번역 원문 수정 후에는 다시 저장해야 생성할 수 있다. 저장 중 원문이 바뀌어도 저장 당시 입력값과 현재 입력값이 다르면 생성 버튼을 활성화하지 않는다.
- 점검표는 저장된 검증 기록이다. `finalEnableAllowed`를 현재 판매 스위치로 표현하지 않는다. 기존 API·운영 절차·공연 공개·판매 설정을 변경하지 않는다.
- 결제·환불·좌석 재판매·특전 실제 반영·회원 권한 변경의 사유/확인/권한 조건을 보존한다. 이번 브라우저 검증에서 실제 결제·환불·고객 답변·권한 변경·특전 배정은 실행하지 않았다.

## 검증과 화면 증거

실제 변경 전 운영 화면과 icons-ip를 확인했다. 변경 후에는 로컬 웹(3012)과 기존 격리 검증 API(8080, DB `127.0.0.1:55432/grabit_journey`)를 이용했다. 운영 DB의 자료를 복제하거나 쓰지 않았다. 화면의 수치는 로컬 검증 데이터다.

전체 17개 메뉴의 실제 렌더링을 확인했다. 공연 등록/판매 준비, 예매 검색/상세, 상세 통계 펼치기와 기간 변경, 메뉴 검색, 입장→특전 이동에서 공연·회차 유지, 모바일 메뉴 닫기와 스크롤 복원도 확인했다. 1440px 데스크톱, 390px 모바일, 320px 공연/공지/입장 화면을 확인했다. 활동 기록 표의 자체 가로 스크롤은 허용하고 페이지 밖으로 넘치거나 글자가 겹치지 않도록 했다.

스크린샷과 검수 기록: `output/admin-redesign-20260922/`, [시각 QA](../../design-qa.md). 이미지 이름의 `before`는 운영의 변경 전 화면, `after` 및 번호 10 이후는 로컬 변경 후 화면이다.

- 웹 단위·컴포넌트 회귀: 전체 118파일/812개 통과. 메뉴 권한/선택 범위, 비동작 판매 버튼 제거, 번역 원문 변경 회귀를 포함한다.
- TypeScript, production build, `git diff --check` 통과. ESLint 오류 0개, 기존 컴포넌트의 hook/img 계열 경고 19개.
- 기존 Playwright E2E 사양은 바뀐 메뉴·접기 동작에 맞췄다. 이번 실행은 연결된 브라우저로 직접 검증했으며 Playwright 러너 전체 실행 결과를 주장하지 않는다.
- DB/API 구현과 스키마는 변경하지 않았다. 실기기 카메라/현장 동시 검표, 실제 결제·환불, 운영자 인수 테스트, production 배포는 이번 UI 검증에 포함하지 않는다.
