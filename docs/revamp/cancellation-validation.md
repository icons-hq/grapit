# 좌석별 취소·환불 검증

대상: [좌석별 티켓·부분취소·환불 상태를 일관되게 제공한다](https://github.com/icons-hq/grapit/issues/218).
기준: `transaction-and-recovery-contract.md`와 기존 구매 시점 취소 정책. 수수료 정책을 새로 도입하지 않는다.

## 구현 계약

- 선택 좌석 견적은 정책·KRW 환불·실제 결제 통화/minor amount·남는 티켓을 반환한다. 최종 요청의 예상 금액이 서버 견적과 달라지면 결제사를 호출하기 전에 거절한다.
- Ticket Item에 취소 명령의 금액·통화·사유/시도 식별자·멱등키를 고정한다. 전체 환불은 같은 내용을 Refund metadata에 저장한다. 새 nullable JSONB column만 추가하며 원 회원·거래·QR 이력을 다시 쓰지 않는다.
- 예매/결제/티켓 row lock 아래 소유권, 기한, 입장·특전 수령, 다른 취소 진행 여부를 검증한다. 취소 대상 QR/특전만 일시 중단하며 결제사 완료 뒤에 취소·재오픈 hold를 확정한다.
- 마지막 좌석도 남길 수수료가 있으면 명시적 부분취소 금액을 보낸다. 외화는 누적 KRW 환불 비율을 minor unit으로 반올림한 누계에서 이전 실제 환불액을 뺀다. 예: USD 1.00의 3석은 0.33/0.34/0.33.
- 늦게 도착한 응답은 현재 명령의 멱등키와 완료/권리 복구 상태를 검사한 뒤에만 기록한다. webhook 완료를 뒤늦은 처리 중 응답으로 되돌리지 않으며, 권리를 복구한 과거 전체 환불을 새 좌석 취소와 연결하지 않는다.
- PG 조회가 실패하거나 잔액/원금이 고정 명령과 다르거나 멱등 기간 15일이 지나면 POST를 재전송하지 않는다. 일치하는 완료 영수증은 시점과 무관하게 복구한다. 명확한 거절과 변하지 않은 PG 잔액을 확인한 경우에만 해당 시도의 QR·특전을 복구한다.
- webhook은 원화 원장 금액 대신 고정된 PG 통화·금액·요청 식별자를 대조한다. 완료 후 DB 실패는 같은 명령 조회로 복구한다. legacy 외화 금액을 KRW 정수 조회에 넣지 않는다.
- 환불의 REQUESTED/SENT/PROCESSING/COMPLETED와 inventory hold/release는 독립이다. 아직 재오픈 절차가 시작되지 않은 NOT_REQUIRED는 재판매 가능으로 표시하지 않는다. 좌석별 재오픈 작업의 singleton key에는 좌석 집합을 포함한다. 완료 환불을 입금 반영 완료로 표현하지 않는다.
- 반복 조회·최종화는 최초 sent/processing 시각을 보존한다. 상태 확인 시각으로 덮어써 타임라인 순서를 뒤집지 않는다. 과거 원장의 시각은 별도 정정 없이 다시 쓰지 않는다.
- 진행 중 취소의 고객 행동은 서버가 지정한 기존 좌석 취소 또는 전체 환불 명령 확인이다. 재시도 시 새로운 견적/사유/멱등키를 만들지 않는다. 거절 후 권리가 복구된 새 요청은 새 시도로 기록한다.
- 확인창은 요청을 기다리며 중복 제출을 막는다. 실패하면 사유·견적을 유지하고 갱신 경로를 보인다. 활성 티켓이 없으면 이메일 재발송을 숨긴다.

## 자동 검증

최종 로컬 검증: API unit **1,300/1,300**, Web unit **748/748**, shared **148/148**, PostgreSQL 통합 **63/63** 통과. API typecheck/build와 Web production build 통과. API lint는 오류 0건이며 기존 경고가 남아 있다. 이후 전체 환불 카드 단계 표시 보완은 관련 단위 88개와 PostgreSQL 해당 사례로 다시 통과했다. CI 결과는 PR에서 별도로 확인한다.

`test/show-relaunch.integration.spec.ts`는 `DATABASE_URL`을 읽지 않고 매 실행 새 PostgreSQL 16 컨테이너를 만든다. PG는 외부 경계의 대역이다.

기존 `ReservationService.cancelTicketItem` 단위 테스트의 private SQL 호출 순서 모킹을 제거하고 다음 동작을 실제 PostgreSQL 통합으로 이전·확장했다. 원화/외화 옵션과 반올림은 `payment-cancel-policy.spec.ts`, hold/재오픈과 재판매 소유권은 finalizer/worker 및 PostgreSQL 테스트에도 유지한다.

| 동작 | 확인한 결과 |
| --- | --- |
| 2석 중 1석 취소, 원금/QR/특전 | 원 Payment.amount 보존, 남는 권리만 활성 |
| 소유권·입장·특전·만료·기한·결제 상태 | PG 호출 전 거절 |
| 동일/다른 좌석 동시 요청 | 고정 명령 재사용, 다른 진행 중 취소 차단 |
| BankPay/Alipay 비동기 | IN_PROGRESS 유지, 완료 조회 뒤 추가 POST 없이 복구 |
| PayPal/해외 카드/Alipay webhook | USD 고정 금액으로 좌석 취소 확정 |
| 응답 유실·같은 금액의 과거 취소 | 시도별 사유/식별자로 현재 요청만 식별 |
| PG 성공/DB 실패 | 권리를 pending으로 보존하고 동일 영수증으로 확정 |
| 마지막 좌석 수수료 | 52,000원 원금에서 46,000원 환불, 6,000원 보존 |
| 외화 3석·재오픈 작업 | 0.33/0.34/0.33, 개별 작업 3개, 총액 상한 |
| 거절 후 권리 복구 | unchanged balance 입증 후 QR/특전 복구, 새 검토 요청 가능 |
| 만료된 멱등키·잔액 변경·조회 실패 | 환불 재전송 없이 확인 필요 상태 |

`seat_key IS NULL` fixture는 migration 0012 이후 NOT NULL 계약과 모순되므로 실행 사례로 유지하지 않는다. canonical seat identity와 재판매 소유권 회귀는 별도 실제 DB 사례로 검증한다.

## 실제 브라우저와 환경 구분

격리 환경은 localhost Web 3000/API 8080, PostgreSQL 55432 `grabit_journey`, Valkey 56379다. migration 전후 예매 9건, 결제 3건, 원금 합계 1,528,000원, Ticket Item 4건, QR 4건이 동일했다. 이후 합성 고객 Mai에 신규 테스트 예매 3건을 추가했다.

브라우저 검증용 결제사 대역은 저장소 밖 artifact의 Node preload다. development + 정확한 격리 DB 주소를 검사하며 `journey_sim_` 테스트 키에만 적용한다. 제품/배포 코드에는 포함하지 않는다. 이 결과는 실제 Toss 승인·카드사 환불 검증이 아니다. 기존 실제 Toss 테스트 승인·전체 취소 증거는 `checkout-validation.md`에서 별도로 관리한다.

- 데스크톱: 2석 중 A1 선택 → 원금 104,000원/환불 52,000원/USD 35.36/남을 A2 확인 → 취소. A1 QR만 폐기하고 A2 QR 유지, 부모 예매와 결제 유지.
- 모바일 390×844: 남은 A2 → USD 35.36 확인 → 취소. 합계 USD 70.72, 활성 QR 0, 재발송 숨김. 실제 pg-boss 재오픈 뒤 available 확인.
- 전체 취소 거절: 104,000원 중 예매 수수료 4,000원 제외, 100,000원 견적. 모의 PG 거절 뒤 확인창·입력 유지, QR 2개 복구. 견적 갱신 후 새 시도에서 100,000원만 환불하고 원금 104,000원/수수료 잔액 4,000원을 보존했다.
- 비동기 부분취소: 처리 중에는 대상 QR만 중단하고 다른 취소 버튼을 숨겼다. 상태 확인을 반복해도 모의 취소 명령은 1개이며, PG 완료를 주입한 뒤 같은 요청 확인으로 환불을 확정하고 남은 QR을 유지했다.
- 부분취소 이후 남은 좌석 전체 취소: 실제 pg-boss가 진행 영수증을 확인하다가 모의 완료를 읽어 자동 확정했다. 총 100,000원 환불, 4,000원 수수료 유지, 활성 QR 0 및 두 좌석 재오픈을 확인했다.
- 전체 비동기 환불의 각 좌석도 Refund의 처리 단계를 따르며, 재오픈 미정(NOT_REQUIRED)을 재판매 가능으로 표시하지 않는다.
- 부분취소 불가라는 과거 안내를 제거하고 선택 좌석/남는 티켓을 명시했다. 영어 QR 안내와 취소 버튼 대비도 실제 화면에서 확인한다.

증거는 로컬 artifact `grapit-revamp-autonomy-2026-09-21/browser/30-*` 이후와 테스트 JSON/log에 저장한다. PG 실제 지출·은행 반영·실제 모바일·외부 wallet 검증은 별도 출시 gate이며 여기서 완료로 간주하지 않는다.
