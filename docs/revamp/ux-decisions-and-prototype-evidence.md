# UX 선택과 조작형 시안 근거

2026-09-21. 사용자가 선택과 후속 작업을 위임했으므로 에이전트가 시안을 선택하고 직접 조작했다. 사용자/직원 인터뷰 결과가 아니다. 현재 제품 구현이나 PG·카메라·서버 동기화 검증의 완료를 뜻하지 않는다.

## 선택한 방향

- 고객: 공연 탐색 → 상세 → 필요한 인증 → 좌석 → 금액 확인/결제 → 같은 주문 복구 → 좌석별 내 티켓. 가장 필요한 공연 정보·좌석·청구 금액·다음 행동을 크게 표시한다.
- 운영: 공연·회차를 선택한 맥락에서 준비/판매/CS/현장/정산을 연결한다. 준비 상태는 단계별 행으로 보여주고 미완료 입력으로 이동한다.
- 현장: 휴대기기에서 회차·좌석·처리 결과와 다음 버튼을 먼저 본다. 입장과 특전 지급을 분리하고 서버 확정과 offline 대기를 구분한다.
- 공통: 흰 배경, 짙은 본문, 보라색 주요 행동, 얇은 구분선, 제한된 강조 패널. 색만으로 상태를 구분하지 않는다. 모바일은 단일 열, 데스크톱 결제는 내용/금액의 두 열이다.

시각 참고는 `concepts/buyer-home-v1.png`, `buyer-checkout-v2.png`, `admin-preparation-v1.png`, `field-mobile-states-v1.png`다. 첫 결제 생성물은 배경 오류로 채택하지 않았다. 모든 가상 공연명·금액·수치는 제품 데이터와 바인딩해야 하며 생성된 공연 포스터를 실제 판매 정보로 사용하지 않는다. 시안의 저장 카드번호 표시는 채택하지 않고 실제 PG 위젯을 사용한다.

## 시안에서 발견하여 고친 점

1. offline에서도 '입장 가능한 티켓' 제목이 남아 있었다. '서버 확인을 기다리고 있어요'로 바꾸고 대기 기록을 완료와 구분했다.
2. 이미 동기화 대기인 좌석의 버튼을 비활성화해 중복 대기 기록을 막았다. 재연결 전 특전 지급 버튼도 비활성화했다.
3. 동의가 기본 선택된 시안을 수정했다. 체크 전 결제 비활성, 직접 체크 후 활성 상태를 브라우저로 확인했다.

제품에 흡수할 결정은 상태/행동 계약이다. 시안의 단순 reducer나 가상 PG·권한·계정 로직을 제품 구현으로 재사용하지 않는다. 외부 결과는 서버가 검증한다.
