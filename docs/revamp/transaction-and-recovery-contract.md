# 거래·복구 계약

2026-09-21 자율 위임으로 선택한 개편 기준. 현재 코드가 이미 모두 만족한다는 문서가 아니다. 거래 소유권, 기존 정책과 원거래 금액을 보존하면서 진단에서 확인한 복귀·통화·환불 상태 문제를 고친다.

## 사실의 주인

예매 상세에서 완료·부분취소·전체취소된 결제의 시각 기록이 없으면 `결제일시 기록 없음`으로 표시한다. 승인·취소 상태가 알려져 있는데 시각이 비어 있다는 이유로 `결제 전`으로 바꾸지 않는다. 원본 시각은 추정하거나 덮어쓰지 않으며 네 언어에서 같은 의미를 유지한다.

홈 배너의 내부 상대주소와 `https://heygrabit.com`/`https://www.heygrabit.com` 절대주소는 선택한 언어로 연결하며 query/hash를 보존한다. 다른 서비스의 주소는 언어 경로를 붙이지 않는다. 기존 배너 원본을 다시 저장할 필요가 없어야 한다.

신규 결제 준비가 400/403/409/422로 확정 거절되어도 그것만으로 기존 주문 부재를 추정하지 않는다. 같은 소유자의 주문 조회가 정상 응답 `null`을 반환한 경우에만 새 시도의 복구 식별자를 지우고 재선택을 제공한다. 조회 실패·기존 주문·응답 유실·5xx·이미 준비된 주문은 원 식별자를 유지한다. PG 인계 이후에는 이 미생성 복구를 적용하지 않는다.

| 사실 | 기준 | 사용자에게 보여줄 의미 |
| --- | --- | --- |
| 판매 가능 좌석 | 회차와 floor-aware Seat Identity의 inventory 및 서버 잠금 | 선택 가능, 다른 구매자가 선택 중, 판매 완료 |
| 대기열 입장 | 서버 admission과 기기/계정 세션 | 구매를 시작할 수 있는 시간. 좌석 소유권과 다름 |
| 예매 의도 | 구매자 소유의 Reservation + 고정 orderId + 좌석/금액 snapshot | 결제 전 예매 내용. 결제 성공 증거가 아님 |
| 결제 | 검증된 공급자 응답·조회와 Payment | 승인/확인 중/실패. 브라우저 query string은 증거가 아님 |
| 관람 권리 | Ticket Item | 좌석별 유효/취소 대기/취소/만료 |
| QR 자격 | Ticket Item의 활성 Credential | QR 교체·폐기와 실제 입장은 별도 |
| 입장·특전 실물 지급 | 좌석별 Admission 및 Benefit Redemption 원장 | 입장 완료와 특전 수령은 각각 표시 |
| 환불 | 해당 취소 요청에 대응하는 공급자 완료 응답·조회 | 접수/처리 중/PG 취소 완료/확인 필요 |
| 재판매 가능 시각 | 취소 완료 후 서버 hold 정책과 inventory 소유권 검사 | 환불 상태와 독립된 좌석 재오픈 |

## 결제 복귀와 시간 경계

1. 선택 좌석으로 처음 준비한 orderId를 서버 Reservation에 바인딩한다. 동일 구매자·회차·좌석·금액의 같은 orderId는 같은 Reservation을 반환한다.
2. 외부 PG로 이동하기 전에 같은 사이트의 복귀 URL에 주문 식별자를 보존한다. 비밀번호·PG secret·QR을 영속 저장하지 않는다. 브라우저 전체 이동, 새로고침, 로그인 복구 뒤 서버에서 소유권과 예매 snapshot을 다시 조회한다.
3. 준비 중인 예매는 Payment가 아직 없어도 조회 가능해야 한다. 화면 메모리에 좌석이나 reservationId가 없다는 이유로 새 주문을 만들지 않는다.
4. 성공 복귀는 서버 confirm 또는 이미 확인된 주문 조회를 통해 발권한다. 확인 중에는 상태 확인·내 티켓 이동만 제공하고 중복 결제 버튼을 활성화하지 않는다.
5. 실패/사용자 중단 복귀도 주문 상태부터 확인한다. 이미 확정됐으면 티켓으로, 유효한 미결제 주문이면 같은 주문 재개로, 종료/만료됐으면 좌석 다시 선택으로 이동한다. failUrl만으로 이미 승인된 거래를 취소하지 않는다.
6. 결제 마감은 서버 UTC deadline을 따른다. 화면 timer가 0이 된 사실만으로 결제 결과를 단정하지 않는다. 늦은 승인은 좌석의 현재 소유권을 확인하고 안전하게 확정할 수 없으면 기존 보상 취소 및 운영 불일치 절차로 처리한다.
7. 서버 상태를 읽지 못하면 '상태 확인 중/다시 확인'으로 남긴다. 네트워크 오류를 결제 실패·0건으로 바꾸지 않는다.

## 금액·취소

- 상품 가격·수수료·원 주문 합계(KRW)와 서버가 고정한 실제 청구 통화·금액을 결제 전, 완료, 예매 상세, 취소 미리보기에 함께 표시한다. 브라우저 환율 재계산으로 PG 금액을 만들지 않는다.
- 환불 견적은 기존 구매 시점 정책과 서버 시각을 사용한다. 고객은 취소할 좌석, 수수료, 원화 환불액, 실제 PG 환불 통화·금액과 남을 좌석을 확인한다.
- 좌석별 취소는 소유권·유효성·입장 여부·특전 수령 여부·정책·PG 부분취소 가능 여부를 검증한 경우만 허용한다. 권리를 이미 사용했거나 외화 원장 근거가 부족하면 이유와 지원 경로를 반환한다.
- 같은 취소의 재시도는 같은 멱등키/공급자 요청 식별자로 조회·복구한다. 서로 다른 좌석의 동시 취소가 결제 잔액을 중복 소비하지 않도록 결제 단위 동시성 경계를 유지한다.
- 마지막 유효 좌석이라는 이유만으로 PG 잔액 전체를 취소하지 않는다. 취소 견적에 남길 수수료가 있으면 그 수수료를 보존한다. 전체 환불 계약인 경우에만 남은 청구액의 반올림 잔액을 함께 정산한다.
- 외화 부분취소는 원 결제의 minor-unit snapshot에 근거한다. 누적 취소액은 원 청구액을 초과하지 않으며 끝자리 반올림 차이와 잔여 수수료를 명시적으로 대조한다.
- PG 성공/DB 실패는 새 취소를 보내기 전에 공급자 조회로 복구한다. 불명확한 응답은 취소 대기로 유지하고 운영 인박스에 남긴다. 불확실한 티켓을 유효로 복구하거나 좌석을 재판매하지 않는다.
- PG 완료와 카드사/은행의 입금 반영은 다르다. 화면에서 공급자 취소 완료는 명시하되 고객 계좌 입금을 확인한 것으로 표현하지 않는다.
- 취소 확정 뒤 모달을 닫고 갱신된 원장·남은 QR을 표시한다. 활성 티켓이 없는 주문의 재발송 버튼은 제공하지 않는다.

## 실패별 책임

| 상황 | 구매자 다음 행동 | 서버/운영 책임 |
| --- | --- | --- |
| 좌석 경쟁·잠금 만료 | 가능한 좌석 다시 선택 | 타 구매자 잠금/소유권을 해제하지 않음 |
| 외부 결제창 중단 | 기존 주문 확인 후 재개 | 무의미한 PENDING 주문 누적 방지 |
| 승인 여부 불명·콜백 누락 | 상태 다시 확인·내 티켓 | 같은 주문 공급자 조회, 진단 이력, 운영 인박스 |
| 중복/역순 webhook | 별도 중복 행동 없음 | 검증·멱등·최종 상태 재조회. 정상/중복 처리 HTTP 200 |
| 일부 취소 처리 중 | 취소 상태 확인, 남은 유효 티켓 사용 | 해당 취소만 대응; 아직 미확정 좌석은 재판매 금지 |
| 확실한 PG 거부 | 이유 확인 후 허용된 재시도/지원 | 기존 권리 복구 시 QR/특전도 일관되게 복구 |
| PG/DB 불일치 | 확인 필요 상태·지원 | 권한 있는 운영자가 근거 조회→대조→사유 있는 조치 |

## 검증 경계

기존 Reservation/Payment 서비스와 실제 HTTP controller를 가장 높은 계약 경계로 쓴다. PostgreSQL/Valkey 통합에서 좌석 소유권·확정·발권·취소·재오픈을 함께 검증한다. 프런트는 실제 페이지를 전체 unmount/remount하여 같은 주문 복구를 확인한다. 공급자 대역 결과와 실제 sandbox 승인·취소 증거를 구분한다.

필수 사례: 다른 계정 주문 조회 거부, 준비 주문 복구, 중복 confirm, 만료 직전/후 승인, 재시도·탭 중복, 2석 중 1석 취소, 마지막 좌석의 수수료 보존, 외화 반올림/총액 상한, PG 성공 후 DB 실패 복구, webhook 정상/중복 200·실패 non-200, 환불과 좌석 hold 상태의 독립 표시.
