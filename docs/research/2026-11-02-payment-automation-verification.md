# 결제 자동화·QR 예약메일 복구 검증 — 2026-11-02

## 범위

QR 예약 안내메일의 발송 직전 프로세스 종료 시 누락을 수정하고, 실금전 거래 없이 결제·취소·환불·웹훅·발권의 회귀를 확인한다. 기준 소스는 운영 `f71458c57e80efae7bd766b733c7a0a63687b800`이다. 기존 작업 디렉터리의 미커밋 변경은 포함하지 않는다.

## 재현과 수정

선점 UPDATE가 커밋된 직후 프로세스가 종료된 상태를 재현했다. 기존 코드의 다음 작업은 `already sent or claimed`로 종료했고, 발송을 요구한 회귀 테스트는 실제 호출 0회로 실패했다. `email_sent_at`을 발송 완료와 선점에 함께 사용한 것이 원인이었다.

리뷰에서 발견한 최초 발송 전 멱등 기간 소진·복구 중 본문 변경에 따른 추가 발송·과거 선점의 완료 오인도 회귀를 추가해 보완했다. 새 `qr_reminder_deliveries` 원장에 예매별 선점 임대·재시도·공급자 접수 영수증을 분리했다. 발송 전 중단은 만료된 임대로 회수하고, 공급자 접수 후 DB 기록 실패는 Resend의 동일 요청 멱등키로 복구한다. pg-boss 작업 유실도 별도 worker 점검으로 다시 처리한다. 기존 발권·결제·환불·입장 상태는 변경하지 않는다. 세부 계약과 23시간 초과 시 대조 절차는 [복구 runbook](../runbooks/qr-reminder-recovery.md)을 따른다.

로컬 기본 Node 26에서는 Web Storage 전역 차이로 웹 테스트 57개가 실패했다. 제품 코드를 바꾸지 않고 CI·운영과 같은 Node 22로 실행해 1,614개 모두 통과했다. 로컬 Docker는 응답하지 않아 통합 테스트의 PostgreSQL 시작 경계만 임시 테스트 어댑터로 대체했다. 매 실행 새로운 loopback PostgreSQL 16 클러스터를 만들고 기존 전체 migration을 적용했으며, 종료 시 제거했다. 임의 `DATABASE_URL`이나 운영 연결을 받지 않는다. 제품 코드·저장소 테스트 helper에는 이 어댑터를 넣지 않았다. CI의 원래 Docker 기반 전체 통합 검증은 연결 PR에서 별도로 확인한다.

추가된 실제 DB 사례는 발송 전 중단 후 임대 회수, 공급자 접수 후 DB 실패의 동일 요청 복구, 동시 작업의 단일 발송, 늦은 과거 작업의 완료·해제 차단, 예약 큐 유실 복구, 취소 좌석 제외, 멱등 기간 초과 시 미발송·확인 필요 상태 보존이다. worker 시작·중복 sweep 방지·종료와 SDK 멱등키/timeout은 단위 테스트로 확인했다.

## 기존 공급자 검증 근거와 남은 범위

국내 카드·해외 카드·PayPal의 테스트 승인/복귀/QR/전액 취소 근거는 `docs/revamp/release-readiness.md`와 #214/#223에 있다. Alipay는 같은 날 별도 테스트에서 USD 35.36 승인 → QR 1개 → 전액 취소 → PG 잔액 0·활성 QR 0, 실제 승인/취소 웹훅 3건의 200 응답, 중복·지연 재생 후 취소 상태 보존을 확인했다. 이 작업에서는 결제사 연동 코드를 바꾸지 않았으며 실결제·실환불을 새로 발생시키지 않았다.

물리 iOS/Android 지갑 앱 전환, 금융기관의 실제 환불 반영, 현장 다중 단말 리허설과 판매 목표 부하는 이 로컬/CI 검증으로 완료 처리하지 않는다. #214/#223은 남은 인수 범위가 있어 OPEN을 유지한다. 실제 배포 SHA·CI·worker·live smoke 결과는 연결 PR의 배포 근거로 기록한다.
